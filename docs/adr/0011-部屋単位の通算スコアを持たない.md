# 0011: 部屋単位の通算スコアを持たない

* ステータス: accepted
* 日付: 2026-08-13

## 決定

共通コアは、1つの部屋で複数ゲームを連続してプレイしたときの通算スコアを持たない。

勝敗と得点は1ゲームで完結し、`nextGame` でロビーへ戻る際に前ゲームの結果を破棄する。
`Room` に `scores` 相当のフィールドを追加しない。

各ゲームの結果は `result` メッセージで開示された時点が終わりであり、部屋が次のゲームへ持ち越す状態は「参加者とそのレベル」だけとする。

## 理由

共通コアがスコアを持つと、収録する全ゲームが共通のスケールで得点を出す義務を負う。

DETECTIVESの結果は市民勝利か犯人勝利かの二値であり、個人の点数がない（[設計.md](../設計.md)）。
DON'T SAY IT は正解数、ESCAPE は脱出の成否と所要時間で、単位が揃わない。
揃わない値を1つの通算スコアに合算する規則を共通コアが定めることは、ゲームのルールを共通コアが決めることに等しく、[ADR-0009](./0009-部屋基盤とゲームモジュールの分離.md)の分離に反する。

共通コアに何かを入れる判断基準は「2本目以降でも確実に必要と言えるか」であり、迷ったらゲームモジュール側に置く（[基本設計/05](../基本設計/05_ゲームモジュール.md)）。
通算スコアはこの基準を満たさない。1本目のDETECTIVESには不要であり、2本目に必要になるかも現時点で確定していない。

代替案として「共通コアが `Record<playerId, number>` の汎用スコアだけを保持し、加算値はゲームモジュールが決める」も検討した。
型としてはゲーム非依存だが、「ゲーム間で加算できる点数が存在する」という前提そのものがゲーム設計上の決めごとであり、共通コアが持つべき前提ではないため採らなかった。

## 影響

* `Room` にスコアのフィールドを置かない。`state` に通算成績が載らない
* 通算成績を出したくなった場合は、共通コアに `scores` を足すのではなく、`nextGame` 時に前ゲームの `result` をゲームモジュールへ引き渡す形で再検討する。この経路であれば、集計の意味を決めるのはゲームモジュールのままになる
* 実プレイで「今日の通算成績を見たい」という要望が出た場合、本ADRを覆す新しいADRを追加する。要望自体は想定される範囲であり、実装を急ぐ理由がないという判断である
* 1つの部屋で連続プレイしたときの体験は「毎回リセットされる単発戦」となる。ロビー画面に前回の結果を表示しない
