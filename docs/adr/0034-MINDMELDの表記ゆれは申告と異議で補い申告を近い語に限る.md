# 0034: MIND MELDの表記ゆれは申告と異議で補い、申告を近い語に限る

* ステータス: accepted
* 日付: 2026-11-12

## 決定

MIND MELDでペアの2語が同じ語かどうかは、**照合キー**（正規化した語から半角空白、ハイフン、アポストロフィを除いた文字列）の完全一致で機械が判定する。

照合キーが一致しない表記ゆれ（複数形、つづりの英米差、1〜2文字の打ち間違い）を、アプリは一致とみなさない。
ペアが「同じ語」と申告し、他のチームの参加者が異議を出し、異議の数で申告を認めるか退けるかを決める。

申告できるのは、2語が**近い語**の条件を満たす場合に限る。
近い語の条件は、照合キーの長さ、先頭部分の一致、編集距離（1文字の挿入、削除、置換の最小回数）だけで決まる。
この条件は申告を受け付けるかどうかの門としてだけ使い、一致の判定には使わない。

編集距離による門は、アプリは英語を理解しないという不変条件1（[ADR-0001](./0001-ランタイムAI不使用.md)）に抵触しない。
根拠は「理由」の「編集距離の門がADR-0001に抵触しない理由」に書く。

正規化の手順、近い語の条件の値、異議の数え方は [基本設計/15](../基本設計/15_MINDMELDゲームモジュール.md) の「語の扱い」を正とする。

## 理由

### 文字列の一致だけでは、同じ語を別の語と判定する

MIND MELDは、ペアの2人が同時に出した英単語がそろえば得点するゲームである。
`apple` と `apples`、`color` と `colour` は、出した2人にとっては同じ語であるが、照合キーは一致しない。

照合キーの一致だけで判定すると、連想がそろっていたのにつづりの差で点を失う。
つづりを覚えきれていないレベル1〜2の参加者ほど打ち間違いが多く、レベル差がそのまま失点として出る。

### 近い語を機械で一致とみなすと、別の語まで一致になる

近い語の条件を満たす組には、`cat` と `car`、`new` と `news` のように別の語が混ざる。
同じ語かどうかは英語の意味で決まり、文字列の比較では区別できない。

意味を判定する主体をアプリに置くことは、ADR-0001が排除している。
そのため、同じ語かどうかの判断は同室の参加者に委ね、アプリは参加者の判断の結果だけを受け取る。

### 申告に門を置かないと、異議の不足に賭けた申告が通る

申告をどの組にも許すと、`pan` と `cook` のような明らかに違う語でも申告できる。
異議が過半数に届かなければ申告は認められるため、異議を出す人が少ない卓ほど、違う語の申告が通りやすい。

4人の卓では判定者が相手ペアの2人だけであり、退けるには2人とも異議を出す必要がある。
近い語に限れば、申告できる組が文字列の上で似た組に絞られ、明らかに違う語の申告は受け付けない。

### 異議は過半数で決める

1人の異議で退ける形では、相手ペアの1人だけで正当な申告を退けられる。
接続中の判定者の過半数を求めることで、1人の異議では申告が退けられないようにした。

異議が誤っていた場合の罰点は置かない。
罰点を与えるには「その異議が誤りだった」を誰かが判定する必要があり、判定の工程がもう1段増えるためである。
代わりに、誰が異議を出したかを公開状態と結果に残し、場の目で抑える。

### 編集距離の門がADR-0001に抵触しない理由

ADR-0001は、本番のアプリからLLM API、音声認識、音声合成を呼ばないことを決め、英文の自動採点を実装しないとしている。
不変条件1はこれを「アプリは英語を理解しない」と要約している。

編集距離の門は、次の3点からこの不変条件に抵触しないと判断した。

1つ目は、計算が文字の比較だけで閉じていることである。
編集距離と先頭部分の一致は、英字の並びを1文字ずつ比べて求める。

辞書、語形変化の表、言語モデル、外部のAPIを使わず、同じ関数は英語以外の文字列にも同じように働く。
運用費も生じない。

2つ目は、門が一致の判定を行わないことである。
門は申告を受け付けるかどうかだけを決め、得点に結び付く判定は照合キーの完全一致か、人の申告と異議で決まる。
近い語の条件を満たしても、申告と異議を経なければ一致にならない。

ADR-0001が実装しないとした自動採点には当たらない。

3つ目は、英文の表層だけを見る判定に先例があることである。
[ADR-0030](./0030-SECRETRULEの規則は表層の判定関数に限り候補を公開する.md) は、不変条件1のもとで、語数や末尾の記号のような表層の条件で英文を判定する形を採っている。
編集距離も文字列の表層の性質であり、意味を解釈しない点で同じ扱いになる。

ただし、近い語の条件の値（先頭部分の差を3文字以下、5文字以上の語で編集距離2まで）は、`child` と `children` や `knife` と `knives` のような英語の語形変化を例に選んでいる。
値を選ぶときに英語の知識を使ったことと、実行時にアプリが英語を理解することは別であり、後者だけが不変条件1の対象である。

## 代案

### 近い語を機械で一致とみなす

申告と異議の工程が不要になり、`reveal` の時間も短くなる。

採らない理由は、前節のとおり `cat` と `car` のような別の語を一致にしてしまうことである。
条件を厳しくして別の語を減らすと、`apple` と `apples` のような本来同じ語の組も拾えなくなる。

### 語形変化の辞書で複数形とつづりの英米差を自動で受理する

複数形の表と英米つづりの対応表を持ち、表にある組だけを一致とみなす案である。

採らない理由は3つある。

* 表は網羅できない。表にない語の複数形は、同じ語であっても一致にならない（[ADR-0030](./0030-SECRETRULEの規則は表層の判定関数に限り候補を公開する.md) が過去形の語彙リストを採らなかったのと同じ理由）
* 末尾の `s` だけで別の語になる組（`new` と `news`）を、表の側で個別に除く必要がある
* 語の意味の資源をアプリへ持ち込むことになり、不変条件1の境界が曖昧になる

### 申告に門を置かず、どの組でも申告できるようにする

近い語の条件で拾えない語形（`mouse` と `mice`、`foot` と `feet`）も申告できるようになる。

採らない理由は、前節のとおり明らかに違う語の申告を異議の不足に賭けて出せることである。
取りこぼすのは不規則な複数形の一部に限られるため、許容する。

### 1人の異議で申告を退ける

採らない理由は、相手ペアの1人だけで正当な申告を退けられることである。

### 誤った異議に罰点を与える

採らない理由は、前節のとおり異議の正誤を判定する工程がもう1段増えることである。

## 影響

* 正規化、照合キー、近い語の条件は `shared/games/mindmeld/` に置き、サーバとクライアントで同じ関数を使う。クライアントは申告のボタンを、サーバが計算した `near` が真のペアにだけ出す
* 近い語の条件の値を変える場合は、[基本設計/15](../基本設計/15_MINDMELDゲームモジュール.md) の改訂で足りる。近い語を一致の判定に使う変更（自動で受理する形）は、本ADRの変更を要する
* 近い語の条件で拾えない語形は申告できない。取りこぼしは不規則な複数形の一部に限られると見込んでいるが、実プレイでの頻度は未検証である
* 異議の多数決には、敵対するチームが正当な申告を退ける余地が残る。抑止は異議を出した人の名前を残すことだけであり、それで足りるかは未検証である
* 文字列の一致で判定しきれない英語の同一性を扱う後続のゲームは、本ADRの形（機械は文字列の比較で門を作り、同じかどうかは人が決める）を参照できる。近い語の条件をゲームをまたいで共通コアへ移すかは、2本目の利用者が出た時点で [ADR-0020](./0020-ゲーム間で重複する部品は共通コアへ置く.md) に従って判断する
