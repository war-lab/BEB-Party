# 0027: ESCAPE CALLの謎はテンプレートとseedから生成する

* ステータス: accepted
* 日付: 2026-09-25

## 決定

ESCAPE CALLの錠（記号の並び、記号と数字の対応表、答え）を `content/escapecall/*.json` に持たない。
`GameModule.start` が、共通コアから注入された `seed` から3つの錠を生成する。

規則（並びをどう変換するか）の意味はコードに置き、`shared/games/escapecall/` の規則IDとして固定する。
コンテンツが持つのは、規則IDごとの英文の言い回し、舞台の文言、質問に使う言い回しである。

生成した錠が解けること（全員の情報を合わせれば答えが一意に決まり、誰か1人の情報を欠くと決まらないこと）は、生成の手順で保証し、多数のseedを回すユニットテストで固定する。
`validate:content` は言い回しの形式だけを検査する。

## 理由

### 手作りのシナリオでは周回できない

2026-08に設計したESCAPE（未マージ。ブランチ `task/escape-設計`）は、錠と手がかりを手作りのシナリオJSONに持ち、推論エンジンで可解性を検証する方式だった。

この方式では、シナリオを1本解いた卓は同じシナリオを二度遊べない。
答えを覚えているためである。
少人数の卓は同じ顔ぶれで続けて遊ぶことが多く、シナリオの消費がそのまま遊べる回数の上限になる。

シナリオ1本の制作には、錠3つ分の手がかりの英文、レベル別の書き分け、推論エンジンでの検証、人手のレビューが要る。
DETECTIVESの事件1本と同程度の負担であり、周回に足る本数を用意できない。

### ADR-0024の条件との関係

[ADR-0024](./0024-BLINDROOMの見本盤面は生成する.md)は、コンテンツを生成に置き換えてよい条件を「作者の判断が入らない」ことと定めた。

ESCAPE CALLの謎は、この条件をそのままでは満たさない。
どの変換を規則として採るか、その規則を英語でどう言うかには、作者の判断が入る。

そこで判断の入る部分と入らない部分を分ける。
規則の種類と言い回しは作者が書き、コードとコンテンツに固定する。
記号の選び方、並び、数字の割り当ては、どれを選んでも遊びとして成立するため、生成に任せる。

ADR-0024の条件は「判断の入る部分を人が書き、判断の入らない部分だけを生成する」と読み替えて適用する。
条件そのものは変えない。

### 可解性を生成の手順で保証できる

錠の答えは「並びに規則を順に適用し、対応表で数字に置き換える」ことで一意に決まる。
生成器は答えを先に決めてから並びと対応表を組むのではなく、並び、規則、対応表を決めてから答えを計算する。
このため、生成した錠には必ず答えがあり、その答えは1つに決まる。

情報の分け方（誰がどの断片を持つか）も生成の手順で決まる。
並びと対応表を別の人に持たせる限り、どちらか一方だけでは答えが決まらない。

推論エンジン（[ADR-0014](./0014-推論エンジンを独立パッケージにする.md)）は使わない。
エンジンが要るのは、手がかりの組み合わせ方が作者ごとに異なり、機械で網羅的に確かめる必要がある場合である。
ESCAPE CALLでは組み合わせ方がコードで固定されており、網羅の対象がない。

## 代案

### 手作りのシナリオJSONを持ち、推論エンジンで検証する

旧ESCAPEの方式である。
物語と謎の質を作者が作り込める。

採らない理由は前節のとおり、周回できないことと、1本あたりの制作負担が重いことである。

### 生成した錠を手作りの舞台設定で包む

錠は生成し、舞台（研究所、船、ホテルなど）ごとに錠の名前と導入文を手作りで持つ案である。

採らないのではなく、舞台の文言だけをコンテンツに置く形で本決定に含める。
舞台の文言は謎の中身に関与せず、どの錠にも付けられる。

### 規則の意味もコンテンツに持つ

規則を「色で除く」「逆から読む」といった汎用の演算の組み合わせとしてJSONで記述する案である。
コードを変えずに規則を増やせる。

採らない理由は、演算の組み合わせ方によっては解けない錠や答えが複数ある錠が作れてしまい、それを検出する検証器が別に要ることである。
規則の数は多くなく、1件足すたびにコードとテストを足す方が確実である。

## 影響

* `content/escapecall/*.json` に錠の答え、並び、対応表を書く欄を設けない。追加した場合、`validateContent` はスキーマ違反として落とす
* 規則を足すときは、`shared/games/escapecall/` に規則IDと変換の実装を足し、全パックに言い回しを足す。言い回しが欠けた規則IDは `validate:content` が落とす
* 錠の再現には `seed` と参加者（人数とレベル）が要る。不具合の再現手順に部屋のseedを含める（BLIND ROOMの見本と同じ扱い）
* 生成器は `start` の中だけで動く。`handleAction` と `onDeadline` にはシードが渡らないため、3つの錠をすべて `start` で生成して `gameSecret` に持つ
* 謎の変化が乏しい（同じ系統の錠を3回解く）ことは、この決定の代償として残る。実プレイで飽きが出た場合は、錠の系統を足すか、規則の種類を増やす（[基本設計/13](../基本設計/13_ESCAPECALLゲームモジュール.md)の未解決の論点）
