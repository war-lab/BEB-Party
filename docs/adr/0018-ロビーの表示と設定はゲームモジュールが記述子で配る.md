# 0018: ロビーの表示と設定はゲームモジュールが記述子で配る

* ステータス: accepted
* 日付: 2026-08-19

## 決定

ロビーに出るゲーム固有の語と設定入力を、`GameModule` が記述子として持ち、`GET /api/catalog` で共通コアへ配る。

```typescript
interface GameModule<...> {
  contentLabelJa: string;          // "事件を選ぶ" / "お題を選ぶ"
  settingsFields: SettingField[];  // 空配列なら設定の入力を出さない
}

interface NumberSettingField {
  type: "number";
  key: string;      // "investigationSeconds" / "roundSeconds"
  labelJa: string;
  min: number; max: number; step: number; default: number;
}
```

共通コアは `key` も `labelJa` も解釈せず、入力を描いて `{ [key]: value }` を組み立て、`configure` の `settings` にそのまま載せる。

`min` と `max` は入力の当たり判定であって検証ではない。
受理の可否は従来どおりサーバの `validateSettings` が決める（[ADR-0012](./0012-ゲーム固有設定の検証をゲームモジュールに委ねる.md)）。

## 理由

2本目のゲームを追加したところ、`client/core/src/components/Lobby.svelte` にDETECTIVES固有の語彙が3箇所あることが分かった。
見出しが「事件を選ぶ」で固定され、「捜査時間（秒）」の数値入力がどのゲームを選んでも出て、`configure` が常に `settings: { investigationSeconds }` を送っていた。

不変条件4（共通コアはゲームを知らない）に反する。
1本目のうちは露見せず、2本目で顕在化した。

DON'T SAY IT側の実害は2つあった。
`roundSeconds` をロビーから変更できず既定値に固定されること、選んでも効かない入力欄が出ることである。

記述子を配る形にしたのは、`title` / `tagline` / `icon` / `playerCount` が既に同じ経路（`GameModule` → `/api/catalog` → ロビー）を通っており、新しい仕組みを増やさずに済むためである。

検討した代替案は2つある。

第一に、`client/app` が `gameId → 設定UIコンポーネント` のテーブルを渡す案（`gameScreens` と同じ形）。
表現力は高いが、現状2ゲームとも設定は「数値ひとつ」であり、ゲームごとにSvelteコンポーネントとパッケージのexportを増やすのは過剰である。
select や toggle が必要なゲームが出た時点で `SettingField` に型を足すほうが、先回りしない方針（[基本設計/05](../基本設計/05_ゲームモジュール.md)）に合う。

第二に、ロビーから設定を廃してゲーム画面の最初のステージで決める案。
ホストがゲームを始める前に長さを決めたいという要求に反するため採らない。

## 影響

* `GameModule` の**必須フィールドが2つ増える**。以後追加するゲームはすべて実装する義務を負う。設定を持たないゲームは `settingsFields` を空配列にする
* `GameSummary` にも同じ2フィールドが載り、`/api/catalog` の応答が変わる
* 表示に出る日本語がサーバ側のゲームモジュールに置かれる。UIの文言をクライアントだけで完結させたくなった場合、この決定を覆すことになる
* 記述子の `min` / `max` と `validateSettings` の受理範囲がずれると、ロビーで入力できる値がサーバに拒否される。両者が一致することをゲームモジュールのテストで固定する
* 選択中のゲームが変わったら、そのゲームの `settingsFields` の既定値で設定を組み直す。前のゲームのキーを残すと、受け取らない側の `validateSettings` へ無関係な値が流れる
* 組み直す条件は `gameId` の変化とする。`Room` の参照を条件にすると、`state` を受信するたびにホストの入力が既定値へ戻る（実測。E2Eで固定した）
* 設定値は公開 `Room` に載らないため、リロードとホスト移譲のあとは新ホストの画面が既定値を表示する。サーバが保持している値との一致は保証しない
