# 0008: 矛盾定義は嘘factを明示的に含める

* ステータス: accepted
* 日付: 2026-08-10

## 決定

`contradictions[].requires` には、**犯人の嘘fact（`lie` が差し替えたfactのid）を必ず含める**。

これに伴い検証項目「単独不可」の判定を「`requires` に含まれるfactのうち、犯人以外が所有するものが2つ以上あり、かつその所有者が2人以上である」と定義する。

## 理由

当初のスキーマ例は `requires: ["f1", "f4"]`（どちらも犯人以外の正直な証言）としていたが、この形では検証項目が両立しない。

嘘factが `requires` に入っていないと、正直な証言だけを投入した状態でも矛盾が発火する。
これは検証項目「冤罪なし（正直な証言のみでは矛盾が1つも導出されない）」に必ず違反する。

逆に「冤罪なし」を通すために矛盾定義を弱めると、今度は「可解性（犯人を一意に指す矛盾が導出される）」が成立しなくなる。

矛盾は本来「犯人の主張と、他者の証言の突き合わせ」で生じるものであり、嘘factを前提に明記するのが意味論として正しい。
これを明示すると、推論エンジンは嘘の有無で挙動を切り替える必要がなくなり、汎用の前方推論器（ESCAPEモードと共用）のままで両方の検証を実行できる。

## 影響

* `requires` は最小で3要素（嘘fact + 他者2人分のfact）になる
* 「単独不可」の判定で嘘factを頭数に数えない。数えると犯人1人 + 他者1人で条件を満たしてしまう
* 「冤罪なし」の検証は、嘘factを投入しない状態で推論を回して結論集合が空であることの確認になる。実装が単純化する
* 5人版（`merge5p` 適用後）は所有者が統合されるため、`requires` の所有者が2人未満になる場合がある。事件データ側で `requires5p` による明示上書きを行う（[04_事件データと検証.md](../基本設計/04_事件データと検証.md)）
