# 0020: ゲーム間で重複する部品は共通コアへ置く

* ステータス: accepted
* 日付: 2026-08-20

## 決定

ゲームモジュール間で重複する部品のうち、**ゲーム固有の概念を含まないもの**は共通コアへ置く。
`server/games/_kit/` と `client/games/_kit/` は新設しない。

3本目のゲーム（案12 ENGLISH RANKING）の着手時点で、次の3つを移した。

| 部品 | 移動元 | 移動先 |
| --- | --- | --- |
| `createRandom` / `shuffle` | `server/games/{detectives,dontsayit}/src/rng.ts` | `shared/core/src/rng.ts` |
| `StageTimer.svelte` | `client/games/{detectives,dontsayit}/src/` | `client/core/src/components/StageTimer.svelte` |
| `acquireWakeLock` | `client/games/{detectives,dontsayit}/src/wake-lock.svelte.ts` | `client/core/src/wake-lock.svelte.ts` |

`pickOne` / `pickWeighted` は利用者がDETECTIVESだけなので移さない。
`StageGuide.svelte` は文言とpropsがゲーム固有であり、共通化できるのは枠と配色だけなので移さない。

## 理由

[実装計画](../実装計画/ゲーム構想20案の収録計画.md)のPR-5は、抽出する場合は `_kit` パッケージを新設し「共有コードを共通コアへ上げない」方針をADRで固定する、としていた。
この前提はその後の作業で変わった。

`client/core` には既に `SecretCover`・`createServerClock`・`formatClock`・演出プリミティブ（`tokens.css`）が入っており、**ゲームモジュールが使う部品を共通コアが提供する形は成立している**。
`_kit` を作ると、同じ性質の部品が置き場所によって2系統に分かれる。

不変条件4が禁じているのは「共通コアがゲームを知ること」である。
今回の3つはいずれもゲームの語彙を持たない。

* `createRandom` / `shuffle`: seedを注入するのは共通コアであり（[基本設計/05](../基本設計/05_ゲームモジュール.md)の呼び出し規約）、注入する側が実装を持つほうが素直である
* `StageTimer`: ステージ名の文字列と締切時刻だけを受け取る。どのラベルを出すかはゲームモジュールが決める
* `acquireWakeLock`: ブラウザAPIの薄い包みであり、どのステージで取るかはゲームモジュールが決める

`_kit` の欠点は、3ファイル・約120行のために workspace パッケージが2つ増えることである。
`package.json`・`tsconfig.json`・eslintの登録・依存の配線が各ゲームパッケージ側にも必要になり、部品の行数より配線の行数が多くなる。

## 判断の線引き

移す条件は次の2つを**同時に**満たすことである。

1. ゲーム固有の語彙（ステージ名・役・証言・お題等）を型にもコードにも含まない
2. 3本目以降で同じ実装が3つ目のコピーになる

条件2を置くのは、先回りの共通化が3本目のルールで想定から外れたときに手戻りになるためである（[基本設計/05](../基本設計/05_ゲームモジュール.md)）。
2本目までは重複を残し、コメントに重複の記録を書いて判断を先送りする運用を続ける。

条件1を満たさないものは、重複していても各ゲームに置いたままにする。
`handleReady`（全員の収集と遷移）がその例で、収集対象と遷移先がゲーム固有であり、共通コアへ上げると進行の判断が共通コア側へ漏れる。

## 影響

* `shared/core` が値（関数）をexportするようになる。従来は型とエラーコードが主だった
* `client/core` の公開物に `StageTimer` と `acquireWakeLock` が加わる。ゲーム追加時はこれらを再実装しない
* 既存2ゲームのimportが `./StageTimer.svelte` から `@beb/client-core` へ変わった。画面の見た目と `data-testid="stage-timer"` は変えていない
* 共通コアの公開面が広がるため、ゲームが増えるほど「共通コアに何を置くか」の判断が繰り返し発生する。判断の線引き（上記）を満たさないものは置かない
* `_kit` を作らない決定であり、条件1を満たさない重複が3つ目に達した場合は、そのとき改めて置き場所を決める（この決定は「共通コアへ置く」以外の選択肢を閉じない）
