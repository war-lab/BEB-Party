# 0022: プレイヤーアイコンはIDで持ち、絵文字は表示層に置く

* ステータス: accepted
* 日付: 2026-08-20

## 決定

参加者が自分のアイコンを選べるようにする。選択肢は共通コアが持つ30件とする。

* 一覧の正本は `shared/core/src/player-icon.ts` の `PLAYER_ICONS`（`id` / `emoji` / `labelJa` の3項）
* プロトコル（`join` の `icon`）と `state`（`Player.icon`）に載せるのは **ID のみ**とし、絵文字は載せない
* `emoji` を読むのはクライアントの表示層に限る。サーバはIDが一覧に含まれるかどうかだけを見る
* `join` の `icon` は省略可とし、省略時はサーバが `playerId` から決まるIDを割り当てる
* アイコンの重複は許す

## 理由

IDと絵文字を分けるのは、アイコンの見た目を後から替えられるようにするためである。
絵文字そのものを `state` に載せると、見た目の差し替えがプロトコル変更になる。
IDで持てば、変わるのはクライアントの対応表と描画だけで、サーバとプロトコルは無変更で済む。

サーバがIDの妥当性だけを見るのは、`state` に載る値の増幅を抑えるためでもある。
`name` に長さ上限を課しているのと同じ理由で（[01_サーバ.md](../基本設計/01_サーバ.md)）、任意長の文字列を無検証で `state` に載せる経路を作らない。
絵文字は見た目が1文字でも符号列としては長くなりうるため、任意の絵文字を受理する形は採らない。

一覧を共通コアに置くのは、アイコンがゲーム固有の概念ではないためである（不変条件4、[ADR-0009](./0009-部屋基盤とゲームモジュールの分離.md)）。
ゲーム画面の顔アイコンも同じ一覧を使うため、対応表をゲームモジュールへ複製しない（[ADR-0020](./0020-ゲーム間で重複する部品は共通コアへ置く.md)）。
ゲーム画面は `gameState` の `playerId` しか持たないので、共通コアが `playerIconOf(playerId)` を提供して受信済みの `state` から引く。

`icon` を省略可としたのは、古いSPAを開いたままのタブが本フィールドを送らないためである。
必須にするとそのタブは `invalid_payload` で参加できなくなる。
互換を壊さない追加なのでプロトコルバージョン `v` は据え置く（[03_プロトコル.md](../基本設計/03_プロトコル.md) の変更手順）。
省略時に固定の既定値ではなく `playerId` から決まる値を割り当てるのは、未選択の席が全員同じ見た目になるとロビーで見分けがつかないためである。

重複を許すのは、選択がロビーに入る前に行われるためである。
ホーム画面の時点では部屋の状態を知らないので、使用済みのアイコンをクライアントが表示できない。
サーバ側だけで重複を弾くと、参加した瞬間に理由の分からない拒否が起きる。
アイコンが同じでも名前とレベルは並んで表示されるため、識別は破綻しない。

30件としたのは、5〜6人の部屋で重複を避けられ、かつスマホの1画面に収まる数の上限だからである。

一覧を動物と架空の生き物だけで構成するのは、絵文字の描画が端末のシステムフォントに依存するためである。
人物のアイコン（髪型・眼鏡・帽子等）を絵文字で表すと、肌色修飾子やZWJによる連結の絵文字を使うことになる。
これらは収録が新しく、端末によっては連結前の部品に分解して描かれるため、見た目が一定しない。
単一の符号位置で表せる動物の顔に限れば、収録が古く描画も安定する。

## 影響

* アイコンを追加・変更するときは `PLAYER_ICONS` を変える。IDを変えるのは互換を壊す変更であり、既存の `sessionStorage` の保存値が無効になる（無効なIDは送信されず、サーバの既定値が割り当てられる）
* 絵文字は端末のシステムフォントで描かれる。サブセットした表示用書体には収録されないため、`.face` は `--font-body` で描く
* 端末によって絵文字の絵柄が違う。同一の見た目を全端末で保証しない
* ロビーで自分のアイコンを変える導線は設けない。必要になった時点で共通メッセージを増やすか、`join` の再送で扱うかを決める（現在の `reconnectToken` 再接続は名前・レベルと同様にアイコンも更新しない）
* 見た目を画像へ替える場合、変更範囲は `PLAYER_ICONS` の表現とクライアントの描画に限られる。プロトコルと `Player.icon` は変えない

## 経緯

| 日付 | 出来事 |
| --- | --- |
| 2026-08-20 | 本ADRを起票。見た目は絵文字（`emoji` 項）で実装した |
| 2026-08-20 | 見た目をドット絵風のPNGへ差し替え、`emoji` 項を削除した。ID一覧も人物12・動物10・その他8の30件へ入れ替えた |
| 2026-08-20 | 素材の作り方を3度変えた（16×16の手描き、128×128の図形合成、生成AIの元絵の48×48への機械変換） |
| 2026-08-31 | 見た目を絵文字へ戻した。`emoji` 項とID一覧（動物30件）を復旧し、PNGと生成の仕組みを削除した |

画像への差し替えと絵文字への差し戻しのどちらでも、プロトコルと `Player.icon` は変わっていない。
本ADRの決定（IDで持つ）が意図した通りに働いた形である。
一方でID一覧そのものは両方向で入れ替わっており、これは互換を壊す変更にあたる（影響の節）。

絵文字へ戻したのは、丸い円の中に置いたときの収まりが絵文字の方が良いという判断による。
ドット絵は正方形の絵柄であり、円形の `.face` に載せると四隅が欠けるか、余白を取って小さく見えるかのいずれかになる。

差し戻しにより、生成AI素材の権利確認という運用上の負担も無くなった。
画像版では生成素材の1件が既存作品のキャラクターと同一の造形になっており、自作の素材へ差し替えて対応していた。
1件混入した実績がある以上、素材を増やすたびに1件ずつ確認する手順が必要だった。
絵文字は端末のフォントが描くため、この確認が要らない。
生成AI素材を再び使う場合の判断基準は `docs/ビジュアルデザイン.md` の権利面の注意に残してある。
