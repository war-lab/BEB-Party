# 0022: プレイヤーアイコンはIDで持ち、絵文字は表示層に置く

* ステータス: accepted
* 日付: 2026-08-20

## 決定

参加者が自分のアイコンを選べるようにする。選択肢は共通コアが持つ30件とする。

* 一覧の正本は `shared/core/src/player-icon.ts` の `PLAYER_ICONS`（`id` / `labelJa`）
* プロトコル（`join` の `icon`）と `state`（`Player.icon`）に載せるのは **ID のみ**とし、見た目は載せない
* 見た目を引くのはクライアントの表示層に限る。サーバはIDが一覧に含まれるかどうかだけを見る
* `join` の `icon` は省略可とし、省略時はサーバが `playerId` から決まるIDを割り当てる
* アイコンの重複は許す

## 理由

IDと見た目を分けるのは、アイコンの見た目を後から替えられるようにするためである。
初期の実装は絵文字で、後にドット絵風の画像へ差し替えた（経緯を参照）。
見た目そのものを `state` に載せると、この差し替えがプロトコル変更になる。
IDで持てば、変わるのはクライアントの対応表と描画だけで、サーバとプロトコルは無変更で済む。

サーバがIDの妥当性だけを見るのは、`state` に載る値の増幅を抑えるためでもある。
`name` に長さ上限を課しているのと同じ理由で（[01_サーバ.md](../基本設計/01_サーバ.md)）、任意長の文字列を無検証で `state` に載せる経路を作らない。
任意長の見た目データ（絵文字の符号列、画像のURL、データURI等）を `join` で受理する形は採らない。

一覧を共通コアに置くのは、アイコンがゲーム固有の概念ではないためである（不変条件4、[ADR-0009](./0009-部屋基盤とゲームモジュールの分離.md)）。
ゲーム画面の顔アイコンも同じ一覧を使うため、対応表をゲームモジュールへ複製しない（[ADR-0020](./0020-ゲーム間で重複する部品は共通コアへ置く.md)）。
ゲーム画面は `gameState` の `playerId` しか持たないので、共通コアが `playerIconOf(playerId)` を提供して受信済みの `state` から引く。

`icon` を省略可としたのは、古いSPAを開いたままのタブが本フィールドを送らないためである。
必須にするとそのタブは `invalid_payload` で参加できなくなる。
互換を壊さない追加なのでプロトコルバージョン `v` は据え置く（[03_プロトコル.md](../基本設計/03_プロトコル.md) の変更手順）。
省略時に固定の既定値ではなく `playerId` から決まる値を割り当てるのは、未選択の席が全員同じ見た目になるとロビーで見分けがつかないためである。

重複を許すのは、選択がロビーに入る前に行われるためである。
ホーム画面の時点では部屋の状態を知らないので、使用済みのアイコンをクライアントが表示できない。
サーバ側だけで重複を弾くと、参加した瞬間に理由の分からない拒否が起きる。
アイコンが同じでも名前とレベルは並んで表示されるため、識別は破綻しない。

30件としたのは、5〜6人の部屋で重複を避けられ、かつスマホの1画面に収まる数の上限だからである。

## 影響

* アイコンを追加・変更するときは `PLAYER_ICONS` と `client/public/player-icons/` の画像を揃えて変える。対応の欠けは `client/core` のテストが検知する
* IDを変えるのは互換を壊す変更であり、既存の `sessionStorage` の保存値が無効になる（無効なIDは送信されず、サーバの既定値が割り当てられる）
* 画像は描画コードから生成した128×128のPNGで、30枚あわせて約24KB（最大の1枚が約1KB）である。絵の正本は描画コードであり、PNGは生成物としてコミットし、CIで再生成との差分を検査する
* ロビーで自分のアイコンを変える導線は設けない。必要になった時点で共通メッセージを増やすか、`join` の再送で扱うかを決める（現在の `reconnectToken` 再接続は名前・レベルと同様にアイコンも更新しない）
* さらに見た目を替える場合も、変更範囲は `PLAYER_ICONS` の表現とクライアントの描画に限られる。プロトコルと `Player.icon` は変えない

画像への差し替えでプロトコルと `Player.icon` は変わっていない。
本ADRの決定（IDで持つ）が意図した通りに働いた形である。

差し替え時に、生成素材の1件が既存作品のキャラクターと同一の造形になっていたため、まずその1件（`blob`）のみ自作のSVGに置き換えた。
その後、残り29件も自作のドットマップへ作り直した。理由は2つある。

1つは権利面である。1件混入していた以上、確認漏れの可能性が残る。
判断基準は `docs/ビジュアルデザイン.md` の権利面の注意とする。

もう1つは素材の性質である。
生成素材はドット絵風でありながらドットの格子を持たず（色数約20万、エッジ間隔3〜15px）、拡大に耐えなかった。
自分で描けば任意の解像度を出せる。副産物としてPNGの合計が198KBから24KBへ減った。

解像度を16×16から128×128へ上げたのは、16×16では目・口・小物を描き分けられず、30件が似た顔に見えたためである。
128×128をマスごとに置くのは現実的でないため、円・楕円・角丸・多角形の重ね合わせで描く方式にした。
