# 0025: BLIND ROOMの盤面アイコンはSVGで持つ

* ステータス: accepted
* 日付: 2026-09-11

## 決定

BLIND ROOMの盤面に置くアイテムを絵文字で描かない。
自作のSVGを `client/public/items/blindroom/<itemId>.svg` に置き、コンテンツは `icon`（ファイル名）を持つ。

* 塗りは5色に限る。`#161B33`（輪郭・黒）/ `#F7F8FD`（白）/ `#FF3D3D`（赤）/ `#2E7CF6`（青）/ `#FFC400`（黄）
* 色違いのアイテムは、同じ図形定義の塗りだけを変えて作る。図形が一致することを `tools` のテストで検査する
* 検査は `tools/src/blindroom-icons.test.ts` に置く。`GameModule.validateContent` はWorkerのバンドルに入るため `node:fs` に触れない（[基本設計/05](../基本設計/05_ゲームモジュール.md)）

この決定はBLIND ROOMの盤面アイコンに限る。プレイヤーアイコンは絵文字のままとする（[ADR-0022](./0022-プレイヤーアイコンはIDで持ち絵文字は表示層に置く.md)）。

## 理由

絵文字は端末のシステムフォントが描くため、同じ符号位置でも絵柄がベンダーごとに違う。
プレイヤーアイコンではこれを許容した。見た目が変わっても、誰の席かは名前とレベルで分かるためである。

BLIND ROOMでは許容できない。
アイテムの見た目は説明の対象そのものであり、名前が主張する属性と描かれる絵が食い違うと、聞き手の能力と無関係に失点する。

収録前のレビューで、絵文字では成立しない組が具体的に挙がった（[お題レビュー/room.md](../お題レビュー/room.md)）。

* `black cat` に使える単一符号位置の絵文字が無い。黒猫 🐈‍⬛ は U+1F408 U+200D U+2B1B のZWJ列であり、端末によって部品へ分解して描かれる
* 🐈 と 🐱 はどちらも茶〜橙の猫で、差は「全身か顔か」である。色の対比を名前に載せられない
* `big star` 🌟 と `small star` ⭐ は同じemサイズで描かれるため、盤面上で大小差が出ない
* 🚙 の色はベンダー任せであり、`blue car` が青く描かれる保証が無い

「色違い・大小違いで修飾語を要求する」という難度設計（[基本設計/12](../基本設計/12_BLINDROOMゲームモジュール.md)のレベル差の吸収）は、色と形を自分で決められないと成立しない。

SVGを選ぶ理由は3つある。

* 拡大縮小で崩れない。同じ絵を見本の85pxと開示の44pxで使う
* 色違いを「同じ図形の塗り違い」として作れる。ラスタ画像を2枚生成すると別の絵になり、聞き手が色ではなく形で見分けられてしまう
* 図形の定義がテキストであり、差分が読める。既存作品との造形の一致を1件ずつ確認する運用（[ビジュアルデザイン.md](../ビジュアルデザイン.md)の権利面の注意）に対して、幾何形状の指定は事故が起きにくい

## 代案

### 名前を絵文字の絵柄に合わせる

`black cat` を `standing cat` に、`big star` を `shiny star` に改名すれば、絵と名前は一致する。

採らない理由は、standardセットが成立しなくなることである。
このセットは「色や大小のような修飾語を言わないと指せない」ことを難度の源にしており、絵柄の差（全身か顔か、輝きの有無）に寄せると、修飾語ではなく別の名詞を言えば済む。
それはeasyセットと同じ遊びである。

### 透過PNGで持つ

生成した絵をラスタで持つ案である。表現力は高い。

採らない理由は2つある。
色違いのペアを画像生成で2枚作ると図形が一致せず、「色だけが違う」という前提が崩れる（1枚を機械的に再着色すれば回避できるが、そのぶん工程が増える）。
もう1つは、生成物に既存作品のキャラクターが混じった実績があることである（[ADR-0022](./0022-プレイヤーアイコンはIDで持ち絵文字は表示層に置く.md)の経緯。30件中1件）。

将来ラスタへ差し替える場合は、コンテンツの `icon` とクライアントの参照先を変えるだけで済む。

## 影響

* `client/public/` にアプリ初のアイコン素材が入る（20点・合計約9KB）。[ビジュアルデザイン.md](../ビジュアルデザイン.md)の「画像アセットを持たない」は、斜め構図と装飾についての方針として残り、盤面アイコンはその例外になる
* 形状の正本は `client/games/blindroom/scripts/generate-icons.mjs` にあり、SVGは生成物である。SVGを直接編集しない（CIの差分チェックが落とす）
* アイテムを追加するときは、形状の定義とコンテンツの両方を足して再生成する。SVGが無いidは `pnpm test` が落とす
* 使われなくなったSVGも `pnpm test` が落とす。コンテンツから外したら同じPRで消す
* 色を増やす場合はこのADRを更新する。5色は色覚特性（2型・1型）でも分離する組み合わせとして選んでおり、赤と緑を同時に使わない
* アイコンはCSSで着色できない（`<img>` で読むため）。色を変える場合はファイルを足す
