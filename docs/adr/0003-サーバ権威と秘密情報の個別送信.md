# 0003: サーバ権威と秘密情報の個別送信

* ステータス: accepted
* 日付: 2026-08-10

## 決定

ゲームルールの判定・タイマー・投票集計はすべてDurable Object内で行う。
秘密情報（証言・犯人フラグ・嘘カード）は該当プレイヤーのソケットへの個別送信（`secret`）と終局開示（`reveal`）でのみ渡し、`state` ブロードキャストに含めない。

## 理由

人狼型ゲームは秘密の漏洩が即座にゲームを壊す。
クライアントに秘密を渡さなければ、DOM改変・開発者ツール・通信傍受のいずれでも自分に配られた情報以上は得られず、チート対策コードが不要になる。

代替案の「全情報をクライアントへ渡して表示だけ制御する」は、スマホブラウザでも通信ログから容易に覗けるため捨てた。

## 影響

* `state` に載せてよいのは全員が見てよい情報のみ。新フィールド追加時はこの観点でレビューする
* 秘密混入を検査する統合テストを常設する（[01_サーバ.md](../基本設計/01_サーバ.md) のテスト観点）
* クライアントは表示と入力のみ。勝敗・時間切れをクライアントで計算して表示する実装は不可
