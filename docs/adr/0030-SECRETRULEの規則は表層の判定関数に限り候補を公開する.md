# 0030: SECRET RULE ENGLISHの規則は表層の判定関数に限り、候補を公開する

* ステータス: accepted
* 日付: 2026-10-06

## 決定

SECRET RULE ENGLISHの秘密の規則は、英文の表層を調べる判定関数に限る。
語数、語の有無、英字の有無、末尾の記号、語の長さ、最初の語の頭文字だけを見て、文法と意味を見ない。

規則の意味はコードに置き、規則IDとパラメータで参照する。
コンテンツは候補ごとに規則IDとパラメータを選び、規則IDごとの英語と日本語の言い回しを書く。

候補は `start` で抽選した6件を最初から全員に公開し、正解はその中から選ぶ。

規則の一覧と判定の定義は [基本設計/14](../基本設計/14_SECRETRULEゲームモジュール.md) の「規則」を正とする。

## 理由

### 規則の説明と判定を一致させる

このゲームでは、卓が候補の文を読んで規則を推理し、その規則に合う英文を書く。
候補の文が述べる条件と、サーバが実際に調べる条件がずれると、規則を正しく読んだ卓が誤答する。

[ルール案](../収録候補ゲームのルール案.md) の案5は、「過去形を使う」を語彙リストとの文字列一致で判定する案を挙げていた。
語彙リストは過去形を網羅できない。
リストにない動詞の過去形を使った英文は、「過去形を使う」という説明を満たしているのに不通過になる。

不変条件1（[ADR-0001](./0001-ランタイムAI不使用.md)）のもとでは、アプリは活用を解析できない。
したがって、文法の概念を規則にすると、説明と判定が必ずずれる。

表層の条件であれば、説明の文がそのまま判定の手順になる。
「6語以上で書く」は語を数えれば確かめられ、卓とサーバが同じ数え方をする。

### 正解を機械で照合できるようにする

原案は、最終ラウンドの後に規則を選択肢から選ぶ形だった。
選択肢を最後まで伏せると、卓は自由に仮説を立てられるが、回答は選択肢から選ぶしかなく、仮説と選択肢がずれる。
自由記述で答えさせると、英語の意味を照合することになり、不変条件1に反する。

候補を最初から公開すると、卓は「どの候補とどの候補を見分ける英文を書くか」を狙って書ける。
回答は候補のidの一致で照合でき、英語を解釈しない。

### 候補を見分けられることを静的に保証する

候補が公開されており、判定関数がコードにあるため、どの英文で候補どうしの成否が分かれるかを機械で計算できる。
検証用の文例集を用意し、候補の母集団の全組について成否が分かれる文があることを `validate:content` で確かめる。

自由な規則（作者が自然言語で書いた規則を人間が判定する形）では、この保証ができない。

## 代案

### 語彙リストで文法の規則を近似する

「過去形を使う」を、過去形の語彙リストのどれかを含むことで判定する案である。

採らない理由は、前節のとおり説明と判定がずれることである。
説明を「次の語のどれかを使う: went, ate, saw, ...」と書き換えれば判定と一致するが、それは `has_word` の規則であり、文法の規則ではなくなる。
`has_word` として収録できるため、別の規則IDを設ける理由がない。

### 候補を伏せ、最後に選択肢を出す

原案の形である。

採らない理由は2つある。
1つは、卓の仮説と選択肢がずれ、推理の途中の議論が回答に結びつかないことである。
もう1つは、候補を見分けられることを、卓が書いた英文に依存せずに保証できないことである。

### 候補ごとに言い回しを書く

候補ごとに自由に英文と日本語を書く案である。

採らない理由は、同じ規則IDの候補どうしで言い回しが揃わなくなることである。
`min_words` の6と8で文の形が違うと、文の違いを規則の違いと読む卓が出る。
言い回しを規則IDごとに持てば、人手で確かめる文の数も規則IDの数まで減る。

## 影響

* 判定関数は `server/games/secretrule/` に置く。`validate:content` も同じ関数を使い、サーバとコンテンツ検証で判定が二重にならないようにする
* クライアントは判定関数を持たない。公式のクライアントは、提出済みの英文から候補を自動で消す表示をしない（理由は基本設計14の「候補を自動で消さない」）
* 規則IDを足すときは、判定関数、パラメータの範囲、言い回しの穴の定義、`validate:content` の検証を同じ変更で足す
* `has_word` と `no_word` は語形変化を扱わない。`cat` を指定した規則は `cats` を満たさない。語の一覧を候補の文にそのまま出すことで、卓に対象の綴りを示す
* 候補の言い回しが判定関数と同じ意味を述べているかは機械で検査できない。人手のレビューで確かめ、記録を `docs/お題レビュー/` に置く
