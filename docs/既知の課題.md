## ロビーがDETECTIVES固有の語彙を持っている（2026-08-18、2本目の追加で顕在化）

`client/core/src/components/Lobby.svelte` に、ゲーム固有の概念が3箇所ある。
共通コアはゲームを知らないという不変条件4（[ADR-0009](./adr/0009-部屋基盤とゲームモジュールの分離.md)）に反する。

| 箇所 | 内容 |
| --- | --- |
| 見出し | 「事件を選ぶ」。DON'T SAY ITではお題セットを選ぶ場面であり、文言が誤っている |
| 設定の入力 | 「捜査時間（秒）」の数値入力（300〜1200）が、どのゲームを選んでも出る |
| `configure` の送信 | 常に `settings: { investigationSeconds }` を送る。ゲーム固有の設定名が共通コアに埋まっている |

DON'T SAY IT側では実害が2つある。
`roundSeconds` をロビーから変更できず既定90秒に固定される。
選んでも効かない「捜査時間」の入力が出る。

`validateSettings` は知らないキーを無視するため、進行そのものは壊れない（実測）。

直し方は `client/app` が `gameId → 設定UI` のテーブルを渡す形（`gameScreens` と同じ構造）が素直である。
ただし共通コアの変更を伴うため、着手前に [基本設計/05](./基本設計/05_ゲームモジュール.md) の境界定義の議論へ戻す（同文書の手順6）。

確度: **実測**（DON'T SAY ITのロビーで「事件を選ぶ」と「捜査時間（秒）」が表示されることを確認）。

## DON'T SAY ITの敵対検証で残した論点（2026-08-18）

4観点の敵対検証（秘密漏洩・進行破壊・不変条件・コンテンツ）で挙がり、修正せず記録した項目である。
致命はなく、成立した攻撃のうち要修正としたものは同PRで直した。

### レベル差の吸収が逆向きに効いている可能性

禁止語を「正解に強く結びつく順」に並べる規約（[基本設計/09](./基本設計/09_DONTSAYITゲームモジュール.md)）のもとでは、レベル1〜2の説明者は**最も強い3語**を奪われ、レベル5は追加で**最も弱い2語**を奪われる。
難度の大半が先頭3語に集中するため、実効難度がレベル1〜2 ≳ レベル5になりうる。
収録セットでは `card_003`（Anpanman）・`card_025`（Yuzuru Hanyu）・`card_028`（Beethoven）が該当し、先頭3語が説明領域のほぼ全部を占める。

並び順の規約を反転するか、提示語数の対応を反転するかは、09の本文と正面から衝突するためADR級の判断になる。
実プレイで得点分布を記録してから決める。

確度: **未検証**（コンテンツの構造からの推論であり、実プレイでの計測はしていない）。

### 制約カードが判定も採点もされない

`WatcherSecret` に制約カードは含まれず、`reportViolation` は禁止語違反と制約違反を区別しない。
レベル5の説明者は制約を無視しても損をしないため、レベル差の吸収のうちレベル5への上乗せ分が名目だけになっている。

制約の遵守を場の指摘に委ねる方針（[構想v2](./構想v2.md)の「やらないこと」）とは整合するが、得点に効かない点は09に明記されていない。

### `verbs_only` が一部のカードで達成不能

制約カード `verbs_only`（`en` は `Use verbs, not nouns.`）は、名詞を禁じると説明手段が残らないカードがある（`card_032` Kumamon、`card_005` Hello Kitty、`card_029` Yoda）。
英文は名詞なしでは事実上書けないため、文言としても厳しすぎる。
`Use as many verbs as you can.` に緩める案がある。

あわせて `no_country` と `no_job` は、地名や職業が既に禁止語であるカードでは負荷が0になる。
制約はラウンド単位で固定されるため、レベル5同士でも回によって負荷が偏る。

### 開示済みのカードが次のゲームの山札に戻る

`nextGame` で `gameSecret` は破棄され、`GameModule` にはゲームをまたいで状態を渡す口がない。
そのため同じ部屋で続けて遊ぶと、前のゲームで開示された人物が再登場する。
09の `usedCards` 節はこの前提に合わせて書き直した（未使用カードを伏せる理由を「振り返りに場に出ていない人物を混ぜない」に変更）。

部屋単位で使用済み `cardId` を持ち越すには共通コアの変更が要るため、[基本設計/05](./基本設計/05_ゲームモジュール.md)の手順6に従い先送りする。

### 検証の受け皿がない警告

`Finding.severity` に `warning` はあるが、`Findings` クラスに `warning()` がないため `warningCount` は常に0である。
近似一致（`kitties` / `Kitty`、`Kumamoto` / `Kumamon`）や単数複数の実質重複（`ninja` / `ninjas`）のように、落とすほどではないが知らせたい項目を追加するには受け皿が要る。

### eslint検査3の抜け道

gameIdリテラルの検査（`eslint.config.js` の `noGameIdLiteral`）は、テンプレートリテラル（`` `dontsayit` ``）・識別子キー（`{ dontsayit: 1 }`）・文字列連結（`"dont" + "sayit"`）を検出しない（実測）。
クォート付きキー（`{ "dontsayit": 3 }`）は検出する。

`registry.ts` が識別子キー形式で書かれているため、同じ形を共通コア側へ複製されると素通りする。
DETECTIVES時代からある既存の限界であり、今回のゲーム追加で生じたものではない。
