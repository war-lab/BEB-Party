# ドキュメントマップ

## 結論

このディレクトリはBEB Partyの全ドキュメントの正本を管理する。

各トピックの正本は1箇所に限定し、他の文書からは参照リンクのみを張る。

コードを変更するPRは、対応する正本ドキュメントの更新を同じPRに含める。

## 読み順

初めて参加する人（人間・AIエージェントとも）は次の順で読む。

0. [../README.md](../README.md): プロジェクトの概要と現在の状況（人間向けの入口。仕様の正本ではない）
1. [../CLAUDE.md](../CLAUDE.md): 破ってはいけない不変条件と規約
2. [構想v2.md](./構想v2.md): 何をなぜ作るか
3. [設計.md](./設計.md): 方式設計（アーキテクチャと技術選定）
4. [開発ガイド.md](./開発ガイド.md): ブランチ・PR・CI・AI協働の進め方
5. [基本設計/05_ゲームモジュール.md](./基本設計/05_ゲームモジュール.md): 共通コアとゲームモジュールの境界（どのコードをどこに書くかの判断基準）
6. 担当モジュールの基本設計（下表）

## 正本ルール

* 同じ事実を2箇所に書かない。要約と参照リンクは可、詳細の重複記載は不可
* ルート `README.md` はGitHubの表紙であり、正本ではない。特徴・技術構成・現在の状況の要約だけを置き、仕様の詳細は書かない。仕様が変わったら要約の記述が古くなっていないかだけ確認する
* 「構造」の正本はコード（`shared/` の型定義）、「意図・不変条件・理由」の正本はドキュメントとする。コードとドキュメントが矛盾したら、まずどちらが正か判断してから直す
* 決定を覆すときはADRを追加し、旧ADRのステータスを `superseded` に変える。本文の書き換えで歴史を消さない
* 長期運用ドキュメントの文章は `ja-writing-style` スキルの規範に従う
