# 基本設計: クライアント（SPA）

## 結論

クライアントは「サーバから届いた状態スナップショットを描画するだけの薄い層」として実装する。

ゲームルールの判定・タイマーの確定・集計をクライアントで行わない。

画面はサーバの `phase` に1:1で追従し、独自の画面遷移状態を持たない。

見た目の規定は [ビジュアルデザイン.md](../ビジュアルデザイン.md)、メッセージの意味は [03_プロトコル.md](./03_プロトコル.md) を正とする。

## 技術構成

* Vite + Svelte + TypeScript。状態管理ライブラリは追加しない（Svelteストアで足りる）
* ルーティングライブラリは使わない。URLは `/`（ホーム）と `/room/:code` の2つだけで、部屋内の画面はサーバの `phase` が決める
* ビルド成果物はWorkerの静的アセットとして配信する

## ストア設計

ストアは3つに分離し、混ぜない。

| ストア | 内容 | 書き込み元 |
| --- | --- | --- |
| `serverState` | `state` メッセージの最新スナップショット | WebSocket受信のみ |
| `secret` | `secret` メッセージ（自分の証言・役割） | WebSocket受信のみ |
| `ui` | 接続状態、入力中の値、演出の進行 | クライアント内のみ |

`serverState` と `secret` へクライアント側のロジックから書き込むことを禁止する。
楽観更新はしない（操作 → サーバ反映 → 再描画の一方向で、パーティゲームには十分速い）。

## 接続管理

* 初回 `join` 成功時にサーバが `joined` で返す `reconnectToken` を `sessionStorage` に部屋コードと組で保存する。`playerId` は認証に使えないので保存しても再接続には使わない（[ADR-0006](../adr/0006-公開IDと再接続シークレットの分離.md)）
* `reconnectToken` は画面に表示しない。URL・ログ・エラー通知にも載せない
* 切断時は指数バックオフ（1s→2s→4s、上限10s）で自動再接続し、`reconnectToken` つき `join` を送る
* 再接続中はUIに接続状態バナーを表示する。ゲーム画面は最後のスナップショットのまま維持する
* タブ復帰（`visibilitychange`）時は即時に再接続を試みる
* `error(unsupported_version)` を受けたら再接続を中止し、`location.reload()` で新しいSPAを取得する。バックオフ再試行を続けると、古いSPAのまま無限にエラーを受け続ける

デプロイ時はすべてのDurable Objectが再起動され、全員のWebSocketが切断される（Cloudflareの仕様）。
上記の自動再接続はこの経路の復帰も兼ねる。

## タイマー表示

サーバの `deadline`（epoch ms）から残り時間を毎秒描画する。

端末時計のずれを吸収するため、`state` 受信時に「サーバ時刻とのオフセット」を推定して補正する（`state` にサーバ現在時刻を含める。プロトコル側の項目参照）。

クライアントの残り0秒はあくまで表示であり、フェーズ遷移は必ずサーバからの `state` で行う。

## 画面と phase の対応

| phase | 画面 | 備考 |
| --- | --- | --- |
| （未接続） | ホーム | 部屋作成 / コード入力 |
| lobby | ロビー | 参加者グリッド、ホストのみ設定と開始。事件一覧は `GET /api/cases`（`CaseSummary[]`）を入室時に取得する |
| briefing | 事件概要 → 配役カットイン | `secret` 受信で役柄演出。readyボタン |
| investigation | 捜査 | 証言カード、制約、タイマー。L1-2は質問テンプレート |
| voting | 投票 | 容疑者グリッド、選択と確定 |
| reveal | 開示 → 振り返り | `reveal` の内容を段階的に演出表示 |

演出（カットイン・ズーム）は `ui` ストアで進行を管理し、`prefers-reduced-motion` では即時表示に落とす。

## 表示モード

* 通常（スマホ縦）: 上記の画面
* ホスト画面: `/room/:code?mode=host`。フェーズ名・タイマー・参加者だけを大きく表示する読み取り専用モード。接続時に `join` ではなく `spectate` を送り、`state` と `reveal` のみを受信する（[03_プロトコル.md](./03_プロトコル.md) の観戦ソケット）。入力系UIは一切出さない

## その他の機能要件

* **Wake Lock**: 捜査・投票フェーズ中は Screen Wake Lock API でスリープを抑止する。非対応ブラウザでは何もしない
* **QRコード**: ロビーの参加用QRはMITライセンスの軽量ライブラリ1つのみ導入可とする（自前実装はしない）
* **オフライン**: 対応しない。切断は再接続バナーで扱う

## 不変条件

* クライアントはゲームルールを判定しない（勝敗・時間切れ・投票集計をクライアントで計算して表示しない）
* `secret` の内容を自分以外に見せるUIを作らない（画面共有的な機能を追加しない）
* `reconnectToken` を画面・URL・ログに出さない
* 証言カードは英文を主、日本語ヒントを従として表示する。英文より日本語を目立たせない（日本語だけ読んで済ませる動機を作らないため）
* 全レベルの捜査画面に「証言は英語で読み上げる」制約を表示する。レベル1〜2も例外にしない

## テスト観点

* Playwright（M0）: 6つのブラウザコンテキストを同時接続し、同じロビー状態が同期すること（M0の完了条件の自動検証）
* Playwright（M2以降）: 部屋作成 → 6人参加 → 開始 → 投票 → 開示の一連導線
* 再接続: 捜査中にWebSocketを切断し、スナップショットが維持されたまま自動復帰すること
* バージョン不一致: `unsupported_version` を返すサーバに対し、再接続ループに入らずリロードが1回だけ走ること
