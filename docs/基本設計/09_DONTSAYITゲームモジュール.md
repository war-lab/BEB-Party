# 基本設計: DON'T SAY ITゲームモジュール

## 結論

DON'T SAY ITは4ステージ（`briefing` / `handoff` / `explaining` / `debrief`）を持つゲームモジュールであり、`GameModule` インターフェースの実装として完結する。

説明者を1人ずつ交代し、参加人数と同じ回数のラウンドを回す。
説明者は人物名を英語で説明し、禁止語を使わずに回答者へ当てさせる。

各ラウンドには説明者・監視役・回答者の3役がある。
監視役を置くのは、回答者に禁止語を見せると正解が割れるためである。

ルールの原案は [収録候補ゲームのルール案.md](../収録候補ゲームのルール案.md) の案13であり、実装順と受入条件は [実装計画/ゲーム構想20案の収録計画.md](../実装計画/ゲーム構想20案の収録計画.md) を正とする。
本文書は、そこで未定のまま残した点を決め、ルールの正本となる。
原案から変更した点は末尾の「原案からの変更」に列挙する。

共通コアとの境界は [05](./05_ゲームモジュール.md)、メッセージの意味は [03](./03_プロトコル.md) を正とする。
共通コアへの追加要求はない。

## ステージ

| stage | 締切 | 遷移条件 |
| --- | --- | --- |
| `briefing` | 120秒 | 接続中の全員が `ready` を送る、または締切到達 |
| `handoff` | 30秒 | 説明者が `startRound` を送る、または締切到達 |
| `explaining` | `roundSeconds`（既定90秒） | 締切到達、または山札が尽きる |
| `debrief` | なし | 遷移しない（`lifecycle: finished`） |

`explaining` が終わると次のラウンドの `handoff` へ戻る。
最後のラウンドの `explaining` が終わったときだけ `debrief` へ進む。

山札が尽きた場合は、残りのラウンドがあっても `debrief` へ進む。
説明するカードがない状態でラウンドを始めても進行できないためである。

そのうえで、1ラウンドでカードを次へ送れる回数に上限を置く。
上限は5回とし、成立・違反・スキップの合計に課す。
上限に達した時点でそのラウンドを終える。

上限がないと、1人が申告を連打して山札を掘り尽くし、残りの参加者が説明者を務められないままゲームが終わる。
流量制限（20通/10秒、[ADR-0017](../adr/0017-メッセージ流量の制限はインメモリで持つ.md)）は連打の速度を落とすだけで、この経路を塞がない。

締切到達時には表示中のカードも捨て札になるため、1ラウンドの最大消費枚数は6枚である。
検証4の山札の下限はこの値から導く（後述）。

`handoff` を独立したステージにするのは、次の説明者が1枚目のカードを読む時間を制限時間の外に置くためである。
`explaining` の締切が動き出してからカードを読むと、1枚目だけ実質的な持ち時間が短くなる。

ラウンド間で得点を表示する専用のステージは置かない。
得点は公開状態にあり、`handoff` の画面で見られる。

## 3役

| 役 | 人数 | 見えるもの | 得点 |
| --- | --- | --- | --- |
| 説明者 | 1 | 人物名、提示された禁止語、制約カード | 成立1枚につき+1、違反1枚につき-1 |
| 監視役 | 1 | 提示された禁止語と正解 | なし |
| 回答者 | 3〜4 | 得点と進行のみ | 自分が当てた1枚につき+1 |

役は毎ラウンド1つずつずれる。
監視役は次のラウンドの説明者とする。
全員が1回ずつ説明者と監視役を務めるため、役割の偏りが出ない。

### 監視役を置く理由

原案は「回答者の誰でも押せる違反ボタン」で違反を扱う。
しかし回答者は禁止語を知らないため、違反したかどうかを判断できない。

回答者全員に禁止語を見せる案は採らない。
禁止語は正解に強く結びつく語であり（`Doraemon` に対する `robot` / `cat` / `pocket`）、5語を並べた時点で正解が割れる。

そのため禁止語を1人へ送り、その人はそのラウンドの回答に参加しないものとする。

監視役には正解も送る。
説明者が正解そのものを口に出したときに押せるボタンが必要であり、それがなければタブー系ゲームで最も基本的な違反を誰も申告できない。
正解の構成語だけを送る案は採らない。語を並べれば正解が復元できるため、隠す体裁だけが残る。

正解を知る役になるため、監視役は加点の対象から外す。
禁止語から正解を推測できる点も同じ理由で吸収される。

5人でも説明者1・監視役1・回答者3が残るため、対応人数の下限は変わらない。

## 公開状態（gameState）

```typescript
interface DontSayItPublic {
  setId: string;
  speakerOrder: string[];        // 説明者の順(playerId)。全ラウンド分を公開する
  roundIndex: number;            // 0始まり
  readyPlayerIds: string[];      // briefingステージの収集状況
  scores: ScoreEntry[];
  rounds: RoundSummary[];        // 終了したラウンドの記録
  solvedThisRound: number;
  violatedThisRound: number;
  skipUsedThisRound: boolean;
  roundSeconds: number;
}

interface ScoreEntry {
  playerId: string;
  points: number;
}

interface RoundSummary {
  speakerPlayerId: string;
  watcherPlayerId: string;
  solved: number;
  violated: number;
  skipped: boolean;
}
```

現在の説明者は `speakerOrder[roundIndex]`、監視役は `speakerOrder[roundIndex + 1]`（最終ラウンドは `speakerOrder[0]`）とする。
専用のフィールドを置くと `speakerOrder` と二重管理になる。

`speakerOrder` を最初に全員へ公開するのは、自分の順番が分かると心構えができるためである。
順番を伏せる利点がない。

`violatedThisRound` を公開状態に置くのは、違反の申告が全員の前で行われる操作であり、伏せる理由がないためである。
ラウンドの集計（`RoundSummary.violated`）を作るのに、進行中の件数をどこかへ持つ必要もある。

人物名・禁止語・制約カード・山札の残り枚数は公開状態に置かない。
`state` は全員へブロードキャストされるため、ここに置いた値は回答者にも届く（[ADR-0003](../adr/0003-サーバ権威と秘密情報の個別送信.md)）。
残り枚数を伏せるのは、あと何枚あるかが分かると回答者が山札の構成を推測できるためである。

## 秘密情報（secret.payload）

送る内容は役によって異なる。

```typescript
type DontSayItSecret = SpeakerSecret | WatcherSecret | AnswererSecret;

interface SpeakerSecret {
  role: 'speaker';
  card: { cardId: string; answer: string; taboo: string[] };
  constraint: { ja: string; en: string } | null;
}

interface WatcherSecret {
  role: 'watcher';
  cardId: string;
  taboo: string[];               // 説明者に提示したものと同じ集合
}

interface AnswererSecret {
  role: 'answerer';
}
```

`handoff` へ入るたびに、その時点の役に応じた内容を全員へ送り直す。
共通コアは `playerSecrets[playerId]` を上書きし差分をマージしないため、役が変わった参加者だけに送ると、前の役の内容が残ったままになる。

カードが次へ進むたびに、説明者と監視役へ新しいカードを送る。
回答者へは送り直さない。
`AnswererSecret` は内容を持たないため、送り直しても変化がない。

説明者と監視役に同じ `cardId` を送るのは、違反の申告がどのカードに対するものかを照合するためである。
監視役の画面が1枚遅れている状態で申告が届いた場合、`cardId` が一致しないため拒否できる。

### 表示文言の定数

回答者の画面に出す呼びかけ（`Is it a person?` / `Say it again, please.` / `One more hint!`）はモジュールの定数とし、コンテンツに持たせない。
セットごとに変わらないためである。

英語に詰まったときの一般的な言い方は共通コアが持つ（[02](./02_クライアント.md)）。
ここに置くのは、当てる側の言い回しに限る。

## レベル差の吸収

説明者のレベルに応じて、提示する禁止語の数を変える。

| 説明者のレベル | 提示する禁止語 | 制約カード |
| --- | --- | --- |
| 1〜2 | 5語のうち先頭3語 | なし |
| 3〜4 | 5語のうち先頭4語 | なし |
| 5 | 5語すべて | 1枚 |

提示する語はカードに書かれた順の先頭から取る。
順序をシャッフルしないのは、どの語を落としても難度が同じとは限らないためである。
コンテンツ側で「正解に強く結びつく順」に並べる（後述の検証）。

制約カードは案17 CHARADES+ を統合した要素であり、説明の仕方に条件を足す（動詞を中心に説明する、3語以内で言う等）。
レベル5にのみ配るのは、禁止語5語と制約の同時付与がレベル4には重いためである。

どの制約カードを配るかは `roundIndex` で決め、ラウンドの途中では変えない。
カードごとに変えると説明の方針が1枚ごとに切り替わり、条件を思い出す時間で持ち時間が減る。
抽選にしないのは、`handleAction` にシードが渡らないためである（[05](./05_ゲームモジュール.md)）。

カードそのものに難度を持たせない。
人物の知名度は英語力と相関しないため、`recommendedLevel` をカードへ付ける意味がない。
山札は1つとし、`seed` でシャッフルして順に配る。

回答者側のレベル差は調整しない。
上級者が正解を独占する可能性は**未検証**であり、実プレイで加点の分布を記録して判断する。
説明者の役が全員に等しく回るため、得点機会の下限は確保される。

## 設定

`settings.roundSeconds` は60秒以上120秒以下の整数とし、既定値を90秒とする。
ロビーの入力欄は `GameModule.settingsFields` の記述子から描かれる（[02](./02_クライアント.md)）。
範囲外・非整数・型違いは `validateSettings` が拒否する（[ADR-0012](../adr/0012-ゲーム固有設定の検証をゲームモジュールに委ねる.md)）。

下限を60秒に置くのは、1枚も成立しないまま終わるラウンドが増えるためである。
上限を120秒に置くのは、後述の所要時間が1晩3ゲームの想定を超えるためである。

## ゲーム秘密状態（gameSecret）

```typescript
interface DontSayItGameSecret {
  deck: string[];                // シャッフル済みのcardId列
  cursor: number;                // 次に配るカードのdeck内位置
  currentCardId: string | null;
  usedCardIds: string[];         // debriefで開示する対象
}
```

`handleAction` と `onDeadline` は呼び出しをまたいで状態を持たないため、山札の順序と現在位置を `gameSecret` に置く（[ADR-0015](../adr/0015-ゲームモジュールの秘密状態を共通コアが預かる.md)）。

山札を公開状態に置けない。
残りのカードが見えると、回答者が正解を先に知る。

`speakerOrder` は公開状態にあるため `gameSecret` には入れない。

## start の処理順

1. `settings.roundSeconds` を確定する（既定90秒）
2. `speakerOrder` を作る。参加者を `seed` でシャッフルした順とする
3. 山札を `seed` でシャッフルし、`cursor` を0にする
4. 各プレイヤーへ役に応じた秘密情報を送る。説明者と監視役には1枚目のカードを送る
5. `stage: 'briefing'`、`deadlineSeconds: 120` を返す

説明者の順にレベルの重みを掛けない。
全員が1回ずつ説明者になるため、順序が有利不利を生まない。
DETECTIVESの犯人抽選（[ADR-0016](../adr/0016-犯人バリアントは重みつき抽選で選ぶ.md)）と扱いが違うのは、あちらが1人だけを選ぶ抽選であるためである。

## カタログ（listContents）

```typescript
interface DontSayItSetSummary extends ContentSummary {
  id: string;
  title: string;
  cardCount: number;
}
```

配るのは公開メタのみとし、人物名・禁止語・制約カードを含めない。

`GameModule` のカタログ用フィールドは次のとおりとする。

| フィールド | 値 |
| --- | --- |
| `title` | `DON'T SAY IT` |
| `tagline` | 禁止語を避けて、英語で人物を説明する |
| `icon` | 🤐 |
| `playerCount` | `[5, 6]` |

`tagline` はあおり文句にせず、何をする遊びかが分かる形にする（[ビジュアルデザイン.md](../ビジュアルデザイン.md)のゲーム選択カード）。
`icon` は書体で描ける絵文字1字とする。

## action の受理規則

| action | 受理stage | 受理条件 | 違反時のコード |
| --- | --- | --- | --- |
| `ready` | briefing | 送信者が参加者 | `invalid_stage` |
| `startRound` | handoff | 送信者が現在の説明者 | `invalid_stage` / `not_speaker` |
| `claimCorrect` | explaining | 送信者が現在の説明者、`playerId` が回答者、`cardId` が現在のカード | `invalid_stage` / `not_speaker` / `invalid_target` / `stale_card` |
| `reportViolation` | explaining | 送信者が現在の監視役、`cardId` が現在のカード | `invalid_stage` / `not_watcher` / `stale_card` |
| `skipCard` | explaining | 送信者が現在の説明者、そのラウンドで未使用、`cardId` が現在のカード | `invalid_stage` / `not_speaker` / `skip_used` / `stale_card` |

これらのコードは共通コアのエラーコード表に含めず、ゲームモジュールが `GameTransition.reject` で返す（[01](./01_サーバ.md)）。

自由英文の提出はない。
判定に使うのは、説明者と監視役のボタン操作と `playerId` の照合だけであり、`action` ペイロードの長さ上限（実装計画のC-1）を必要としない。

連打の抑止はモジュール側に置かない。
共通コアがソケットごとに20通/10秒の流量制限を持つ（[ADR-0017](../adr/0017-メッセージ流量の制限はインメモリで持つ.md)）。
1枚の説明に数秒以上かかるため、実プレイでこの上限に届かない。
一方でE2Eは人手より速く押せるため、通し検証では申告の間隔を空ける必要がある。

### ready

DETECTIVESと同じ扱いとする（[08](./08_DETECTIVESゲームモジュール.md)）。
すでに `readyPlayerIds` に含まれる送信者からの `ready` は、状態を変えずに受理する。

接続中の全員が揃ったら最初の `handoff` へ遷移する。

### startRound

`explaining` へ遷移し、`deadlineSeconds` に `roundSeconds` を設定する。

説明者に限るのは、カードを読み終えたかどうかを知っているのが説明者だけだからである。

### claimCorrect

回答は口頭で行われるため、誰が当てたかをサーバは観測できない。
説明者の申告を正とする。

処理は次のとおり。

1. `scores` の説明者と `playerId` に各+1
2. `solvedThisRound` を1増やす
3. 現在のカードを `usedCardIds` へ加え、次のカードを説明者と監視役へ送る
4. 山札が尽きたらそのラウンドを終える（残りのラウンドがあっても `debrief` へ進む）

対象に選べないのは、説明者自身と現在の監視役である。
監視役は禁止語を見ているため、当てても加点しない。

### reportViolation

現在のカードを無効にする。

1. `scores` の説明者に-1
2. そのラウンドの違反件数を1増やす
3. 現在のカードを `usedCardIds` へ加え、次のカードを説明者と監視役へ送る

申告の取り消しは設けない。
取り消しを許すと、誰がどの時点まで取り消せるかの規則が必要になる。
影響は1枚分の減点にとどまるため、誤操作は場の合意で次のカードに反映するほうが早い。

### skipCard

現在のカードを飛ばす。得点は動かさない。

1ラウンド1回に限る。
知らない人物のカードで持ち時間が潰れるのを防ぐ一方、回数を制限しないと、説明しやすいカードが出るまで山札を掘れる。

## onDeadline

| stage | 遷移先 | 未入力者の扱い |
| --- | --- | --- |
| briefing | 最初の handoff | 未readyを既読扱いにする |
| handoff | explaining | 説明者が操作しなくても開始する |
| explaining | 次の handoff、または debrief | — |
| debrief | 遷移しない | — |

`explaining` の締切到達で、そのラウンドを終える。
`rounds` に集計を追加し、`solvedThisRound` / `violatedThisRound` / `skipUsedThisRound` を戻す。

当てられなかったカードは捨て札にし、次のラウンドは新しいカードから始める。
持ち越すと、場が既に聞いた人物を次の説明者が説明することになり、回答者が答えを知った状態から始まる。

最終ラウンドでも同じ3つのカウンタを戻す。
`rounds` と進行中のカウンタを足し合わせて集計する画面が、最終ラウンドを二重に数えないようにするためである。

`handoff` で説明者が未接続の場合は、そのラウンドを飛ばして次の `handoff` へ進む。
未接続の参加者を待って進行が止まらないようにする。

このとき表示中のカードは山札から落とすが、`usedCardIds` へは積まない。
`explaining` に一度も入っていないカードは誰も見ていないため、結果画面で開示してはならない。

監視役が未接続の場合はそのまま進める。
違反の申告がないまま進むが、進行は止まらない。

`debrief` には締切を置かない。
`lifecycle: finished` で `nextGame` を待つ（[01](./01_サーバ.md)）。

## 得点

| 事象 | 説明者 | 正解した回答者 |
| --- | --- | --- |
| カード成立 | +1 | +1 |
| 違反で無効 | -1 | — |
| スキップ | 0 | — |

説明者と正解者の双方に加点するのは、説明者が伝わりやすさを優先するようになり、発話量が増えるためである。
説明者だけに加点すると、難しい言い換えで時間を使う戦略が有利になる。

得点は1ゲーム内で閉じる。
複数ゲームをまたぐ通算は持たない（[ADR-0011](../adr/0011-部屋単位の通算スコアを持たない.md)）。

同点の扱いは決めない。
順位は表示するが、勝者を1人に絞る必要がない。

## 結果（result.payload）

```typescript
interface DontSayItResult {
  scores: ScoreEntry[];          // points降順
  rounds: RoundSummary[];
  usedCards: { answer: string; taboo: string[] }[];
  keyExpressions: { en: string; ja: string }[];
}
```

`usedCards` は使い終えたカードだけを開示する。
未使用のカードを開示しない。

理由は、そのゲームで場に出ていない人物を振り返りに混ぜないことである。
「同じセットを次のゲームでも使うため」ではない。
`nextGame` で `gameSecret` は破棄され、`GameModule` にはゲームをまたいで状態を渡す口がないため、次のゲームの山札はセット全件から作り直される（使用済みのカードも戻る）。
同じ部屋で続けて遊ぶ場合に開示済みの人物が再登場する点は、[既知の課題](../既知の課題.md)に記録する。

所要時間と各カードの経過秒を結果に含めない。
`handleAction` と `onDeadline` は時刻に触らないため、モジュール側で計測できない（[05](./05_ゲームモジュール.md)）。

## 所要時間の見積り

6人・`roundSeconds` 90秒の場合の合計は次のとおり。

| 区間 | 秒 |
| --- | --- |
| briefing | 120 |
| handoff × 6 | 最大180 |
| explaining × 6 | 540 |
| 合計 | 最大840（14分） |

`handoff` は説明者が操作すれば短くなるため、実際は12分前後を見込む。

この見積りは**未実測**である。
人数分のラウンドを回す案が1ゲーム10分を超える点は、ルール案でも未解決の論点として挙がっている。
実プレイで測り、超過する場合は `roundSeconds` の既定値を下げるか、ラウンド数を人数より減らす。

## コンテンツ形式

`content/dontsayit/<id>.json` に静的JSONとして置く（[ADR-0004](../adr/0004-事件データの静的JSON化とCI検証.md)と同じ方針）。
スキーマの正本は `shared/games/dontsayit/` の型定義とし、以下は説明用とする。

```jsonc
{
  "id": "world_figures_v1",
  "title": "World Figures",
  "cards": [
    {
      "id": "card_001",
      "answer": "Doraemon",
      // 正解に強く結びつく順に並べる。レベル1〜2の説明者には先頭3語だけを提示する
      "taboo": ["robot", "cat", "pocket", "future", "Nobita"]
    }
    // ... 36枚以上
  ],
  "constraints": [
    { "id": "verbs_only", "ja": "動詞を中心に説明する", "en": "Use verbs, not nouns." }
    // ... 1枚以上
  ],
  "keyExpressions": [
    { "en": "He is the one who ...", "ja": "〜した人です" }
  ]
}
```

カードidはセット内で一意とする。
`gameSecret` の山札がidでカードを指すため、重複していると別のカードを引ける。
この検査は検証項目ではなく構造検証（`schema`）として扱う。

推論エンジンを使わない。
DON'T SAY ITの検証は文字列比較と枚数の計数で足りるため、`shared/engine` へ依存しない。

コンテンツ形式を別文書に分けず本文書に置く。
DETECTIVESが [04](./04_事件データと検証.md) と [06](./06_推論エンジンと検証アルゴリズム.md) に分かれているのは、検証が前方推論の意味論を必要とするためであり、ここにはその事情がない。

## 検証項目

`validateContent` が次を検査する。

| # | 検証 | 判定 |
| --- | --- | --- |
| 1 | 正解の非露出 | 各カードの禁止語に、正解名を構成する語が含まれない |
| 2 | 禁止語の重複なし | 1枚のカード内で禁止語が重複しない |
| 3 | 禁止語の語数 | 各カードの禁止語がちょうど5語である |
| 4 | 山札の枚数 | カードが36枚以上ある |
| 5 | 制約カードの存在 | `constraints` が1枚以上ある |
| 6 | 表示完全性 | `title` / 各カードの `answer` と `taboo` / 各制約の `ja` と `en` / `keyExpressions` が揃っている |
| 7 | 正解名の文字種 | `answer` が英字・空白・ハイフン・アポストロフィのみで構成される |
| 8 | 正解の一意 | 正規化した `answer` がセット内で重複しない |
| 9 | 禁止語の形 | 各禁止語が英字・空白・ハイフン・アポストロフィのみで、2語以内、1語15文字以内である |

判定手順のうち、誤解しやすいものを以下に定める。

### 検証1の比較単位

`answer` を空白とハイフンで分割し、各語を小文字化して比較する。
禁止語も同じ正規化を行い、**語単位の完全一致**を落とす。
部分一致は採らない。

`Michael Jackson` に対する禁止語 `Michael` は不合格である。
禁止語がそのまま正解の一部であると、説明者は最初の1語で詰む。

複合語の禁止語（`time machine`）は許す。
分割して各語を比較する。

部分一致で判定してはならない。
正解に短い語が含まれると無関係な禁止語まで拒否する（`Winnie the Pooh` の `the` により `mother` / `brother` / `father` が書けなくなる。実測）。

正解の構成語そのものを禁止語に書けない点は、監視役へ渡す正解が吸収する。
`Mickey Mouse` の `mouse` のように正解が一般名詞を含む場合、その語は明示的な禁止語にできないが、監視役が正解を見ているため口に出せば違反を押せる。

### 検証3が5語固定である理由

提示する語数はレベルで変えるが、収録するのは常に5語とする。
3語しか収録しないカードがあると、レベル5の説明者に配れない。

### 検証4の下限

1ラウンドの最大消費枚数から導く。
消費できるのは「カードを次へ送れる回数の上限5回」と「締切到達時に捨てる表示中の1枚」で、合わせて6枚である。
`playerCount` の上限が6であるため、6×6=36枚を下限とする。

締切時の1枚を数え落とすと、最後の説明者に順番が回らない山札が検証を通る。
実測では、32枚のセットで各ラウンド5枚成立させると成立数が `[5,5,5,5,5,2]` になり、30枚では6人目に順番が回らなかった。

1ラウンド90秒で成立する枚数は、実測前の見積りで3枚から5枚である。
この見積りは**未実測**であり、実プレイで1ラウンドあたりの消費枚数を記録する。

### CLIへの登録

`tools/src/validate-content.ts` の `validators` へ、`content/dontsayit` と検証関数の組を1行足す。

反例の整形関数（`formatFinding`）もゲーム側から渡す。
共通ランナー（`tools/src/validate/run.ts`）は反例の欄を知らず、整形済みの行だけを受け取る。
ランナーが特定のゲームの `Finding` 型を知ると、ゲームを追加するたびに出力の欄が増え、CLIがゲームごとに分岐する。

単一ファイル検証は、渡されたパスがどのゲームの `content/` 配下かで検証を選ぶ。
ゲームが1本のうちは呼び出し側が固定で渡せたが、2本目からは判別が必要になる。

### 検証9が文字種を英字に限る理由

非ASCIIの禁止語はフォントサブセットの入力に含まれず、画面で豆腐になる。
`client/app/scripts/generate-font-subsets.mjs` は日本語フィールド（`ja` 系）からしか文字を集めないため、`taboo` に書いた仮名や漢字はサブセットへ入らない。

数字とアクセント付き文字を落とすのは、検証1の完全一致をすり抜けて正解を露出させる経路になるためである（`Pikachu` に対する `P1kachu` / `Pikachú`）。

語数を2語以内に限るのは、多語の言い換え（`blue cat from the future`）を禁止語に書くと、監視役が「その語を言ったか」を判定できず枠が死ぬためである。

### 機械で検査しないもの

参加者が人物を知っているかは機械で判定できない。
セットを追加するときは、想定する参加者層に対して人物の知名度を人手で確認する。
確認の記録は、事件データと同じ形式でセット単位に残す（[事件レビュー/](../事件レビュー/)に相当する記録）。

禁止語の並び順が「正解に強く結びつく順」になっているかも機械では判定できない。
レベル1〜2の説明者に配る先頭3語が、実際に説明の難所になっているかを人手で確認する。

## 原案からの変更

[ルール案](../収録候補ゲームのルール案.md)の案13から変えた点と、その理由を挙げる。

| 変更 | 理由 |
| --- | --- |
| 違反の申告者を「回答者の誰でも」から監視役1人へ | 回答者は禁止語を知らないため違反を判断できない。全員に禁止語を見せると正解が割れる |
| 提示する禁止語の数をレベルで変える | 原案は5語固定で、レベル差の吸収が制約カードだけに寄っていた |
| 制約カードをレベル5のみへ | 禁止語5語と制約の同時付与はレベル4には重い |
| スキップを追加（1ラウンド1回） | 知らない人物のカードで持ち時間が潰れる経路を塞ぐ |
| `handoff` ステージを追加 | 1枚目を読む時間を制限時間の外に置く |
| カードに `recommendedLevel` を持たせない | 人物の知名度は英語力と相関しない |

## テスト観点

`GameModule` は純粋関数のため、Durable Objectなしで全項目をテストする。

* 決定性: 同じ `seed` と同じ参加者から、同じ `speakerOrder` と同じ山札の順序が得られること
* 秘密の非混入: `DontSayItPublic` に人物名・禁止語・制約カード・山札の残り枚数が現れないこと
* カタログの非混入: `listContents()` の戻り値に人物名と禁止語が含まれないこと
* 役の巡回: 6人で6ラウンド回したとき、全員が1回ずつ説明者と監視役になること
* 監視役の秘密: `WatcherSecret` に `answer` が含まれないこと
* 禁止語の提示数: レベル1〜2の説明者に先頭3語だけが渡り、レベル5に5語と制約カードが渡ること
* 監視役の禁止語: 説明者に提示した集合と一致すること（語数が違うと違反の判断がずれる）
* 役の切り替え: `handoff` のたびに全員へ秘密が送り直され、前の役の内容が残らないこと
* `claimCorrect`: 説明者自身と現在の監視役を対象に選べないこと
* `claimCorrect`: 古い `cardId` の申告が `stale_card` で拒否され、得点が動かないこと
* `reportViolation`: 監視役以外が `not_watcher` で拒否されること
* `reportViolation`: 説明者の得点が1減り、回答者の得点が動かないこと
* `skipCard`: 2回目が `skip_used` で拒否されること
* `skipCard`: ラウンドが変わると再び使えること
* 山札: 尽きた時点でそのラウンドが終わること
* 未接続: `handoff` で説明者が未接続のラウンドが飛ばされ、進行が止まらないこと
* 締切: `explaining` の締切到達で `rounds` に集計が追加され、`solvedThisRound` が戻ること
* 遷移: 最後のラウンドの終了で `result` が返ること
* 結果: `usedCards` に使い終えたカードだけが入り、未使用のカードが含まれないこと
* 消費上限: 上限に達した時点でラウンドが終わり、`rounds` に集計が入ること
* 消費上限: 違反とスキップも上限に数えること
* 消費上限: 1人が連打しても、6人分のラウンドが回りきる前に山札が尽きないこと
* 飛ばしたラウンド: `handoff` で説明者が未接続のとき、そのカードが `usedCardIds` に入らないこと
* 最終ラウンド: `debrief` へ進んだ時点で3つのカウンタが戻っていること
* 監視役の秘密: 正解と禁止語を持ち、`cardId` が説明者と一致すること
* 回答者の秘密: 正解も禁止語も含まれないこと
