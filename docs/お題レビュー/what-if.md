### 作成時の自己点検

複数観点のクロスレビューは実施していない。
作成したAIエージェント1体（モデル: Claude Opus 5.5）が、[日常](./daily.md) のクロスレビューで使った3観点を1人で順に当てて自己点検した。

観点どうしの独立性はない。
1人の判断であるため、日常の記録にあるような観点間の衝突と裁定は起きていない。

| 観点 | 点検した内容 |
| --- | --- |
| A | 回答の分散と作者当ての成立性 |
| B | 英語の質と難度適合 |
| C | 場の安全性とパーティゲームとしての面白さ |

#### 観点Aの点検（回答の分散）

12件とも、答えが書き手の好みで決まる質問である。
知識を問う質問は入れていない。

収束が起きやすいと見積った質問は次の3件である。

* `q_million_yen`: 旅行や貯金へ寄る可能性がある
* `q_live_anywhere`: ハワイなど定番の地名へ寄る可能性がある
* `q_clone`: 「仕事をさせる」へ寄る可能性がある

いずれも、続く語（誰と、なぜ、何の仕事を）で1文全体には差が出ると判断し、収録した。
見積りであり、実測していない。

`q_movie_title` と `q_talking_object` は、創作を求めるため収束が最も起きにくいと見込んだ。

#### 観点Bの点検（英語の質と難度）

12件のうち8件が `If ..., what would ...?` の仮定法の文である。
仮定法過去（`If you could`、`If your life were`）はレベル1〜2には読みにくい可能性がある。
`ja` は12件中10件に「〜なら」「〜たら」の条件節を置き、条件と問いを取り違えないようにした（`q_instant_skill` と `q_younger_self` は条件節を持たない）。

この段落は当初「`ja` を全件『〜なら、〜？』の形にした」と書いていたが、独立レビューで実態と違うと分かり、記述を直した。

`hintEn` は1件目が最も平易になるよう並べた。
1件目は `I would be a ... for a day.` や `I would live in ...` のように、質問文の `would` をそのまま受ける形にした。
レベル3以上には1件目だけが配られるため、1件目だけで答えの骨格が作れるようにしている。

`q_younger_self` の1件目 `Do not worry about ...` は、10歳の自分へ直接語りかける命令文である。
`I would tell myself to ...` を1件目にしなかったのは、`tell myself to` の構文が命令文より難しいと判断したためである。

`q_swap_lives` の2件目 `I want to try ...'s life.` は、空欄の直後に所有格の `'s` が付く。
空欄へ名前を入れれば成立するが、`...` ごと写した場合は読みにくい文になる。
枠として成立しており、検証10の目的（完成文を配らない）には反しない。

#### 観点Cの点検（場の安全性と面白さ）

家庭環境に依存する質問を避けた。
`q_million_yen` の3件目は、家族を前提にしないよう `I would give half of it to ...` とした。

注意を要する質問は次の2件である。

* `q_swap_lives`: 同室の参加者の名前を書くことができる。好意的な文脈になる見込みだが、特定の参加者をからかう答えが出る可能性はある
* `q_dinner_anyone`: 亡くなった人を挙げる参加者がいる可能性がある。英語圏の定番の質問（`living or dead`）の形は避け、範囲を示さない文にした

いずれも、作者が `judging` で開示される点は日常と同じである。
隠し通しの1点が、無難な答えを書く動機として働く見込みもある。

面白さの見込みが高いのは `q_movie_title`（人生の映画の題名）、`q_talking_object`（しゃべる持ち物）、`q_new_holiday`（新しい祝日）である。
答えの意外さに書き手の個性が出やすい。

### 独立レビュー（2026-09-30）

#### 実施主体と観点

作成者とは別のAIエージェント1体（モデル: Claude Opus 5.5）が、作成時の記録を読んだうえでレビューした。
作成AIとはコンテキストを共有していない。
ただし同じモデルであり、4観点を1体で当てた点は自己点検と変わらない。

| 観点 | 内容 |
| --- | --- |
| 1 | 質問文、`hintEn`、`keyExpressions` が自然な英語か。`hintEn` の枠が文として成立し、1件目ほど平易か |
| 2 | 日本語訳が正確で、英語と意味が一致するか |
| 3 | 答えに書き手の個性が出て、一意に収束しないか。140字と4語以上の制約で答えられるか。日常や他ゲームと重複しないか |
| 4 | 同室の参加者に踏み込みすぎる質問がないか |

#### 立てた評価基準

`hintEn` の1件目は全員に届き、レベル3以上には1件目だけが届く。
1件目の空欄が名詞1語だけを受ける形だと、答えが定番の名詞へ寄る質問では、別の参加者が一字一句同じ文を出しうる。
たとえば `q_animal` の旧1件目 `I would be a ... for a day.` では、猫を選んだ2人がどちらも `I would be a cat for a day.` を出しうる。

この基準は、定番解への寄りが強いと判断した質問にだけ適用した。
該当する質問は、1件目へ理由や行動を書く2つ目の空欄を足した。
寄りが弱いと判断した質問の1件目は、名詞1語の枠のまま残した（日常の `q_desert_island` も同じ形で収録されている）。

#### 指摘と対処

| 箇所 | 観点 | 指摘 | 対処 |
| --- | --- | --- | --- |
| `q_instant_skill` | 3 | 英語を学ぶ卓では「英語を話せるようになりたい」へ寄りやすい。作成時に言語の候補を「英語へ収束しうる」として外し、この質問へ統合したため、外したはずの寄りがここに残っていた | `What strange skill would you like to learn overnight?`、「一晩で身につけたい、変わった技能は？」へ |
| `q_animal` | 3 | 猫や鳥へ寄りやすい。1件目が名詞1語の枠 | 1件目を `I would be a ... and ...`、2件目を `I want to be a ... because ...` へ |
| `q_live_anywhere` | 3 | ハワイなど定番の地名へ寄りやすい。1件目 `I would live in ...` が名詞1語の枠 | 1件目を `I would live in ... because ...` へ。3件目 `I would move to ... because ...` は1件目と同じ型になるため `Life in ... would be ...` へ |
| `q_swap_lives` | 1 | 2件目 `I want to try ...'s life.` は `try someone's life` の結びつきが弱い。空欄の直後に `'s` が付き、`...` ごと写すと文が崩れる | `I want to live like ... because ...` へ |

| 記録の記述 | 2 | 作成時の観点Bに「`ja` を全件『〜なら、〜？』の形にした」とあった。実際は `q_instant_skill` と `q_younger_self` に条件節がなく、`q_million_yen` などは「〜たら」である | 記述を実態に合わせて直した |

#### 直さなかった点

| 箇所 | 観点 | 判断 |
| --- | --- | --- |
| `q_swap_lives` | 4 | 同室の参加者を名指しでき、相手の私生活（家族、収入）を話題にする読みも生む。範囲を有名人に絞る案は下記の理由で判断が分かれるため、直さなかった |
| `q_dinner_anyone` | 4 | 亡くなった家族を挙げる参加者が出うる。作成時の記録どおり、範囲を示さない文で維持した |
| `q_younger_self` | 4 | 後悔やつらい時期を書かせうる。1件目の命令文 `Do not worry about ...` は軽い助言へ誘導するため維持した |
| `q_million_yen`、`q_clone` | 3 | 旅行や「仕事に行かせる」へ寄りうる。`q_clone` の1件目は動詞の空欄を持ち、文全体は分かれると判断した。`q_million_yen` の1件目 `I would buy a new ...` は名詞1語の枠だが、買う物の候補は `q_animal` より広いと判断して維持した。見積りである |
| `keyExpressions` | 1、2 | 9件とも自然な英語で、`ja` と意味が一致する。`Would you really do that?` と `It was not me.` は疑われた側が返す型として働く。変更なし |
| 他パックとの重複 | 3 | 日常の仮定6件と ENGLISH RANKING の質問文を照合した。`q_live_anywhere` は RANKING の `What makes a town a great place to live?` と題材が近い。RANKINGは条件の順位づけで、こちらは地名と理由を書くため、答えの形が違うとして維持した |

`q_swap_lives` の範囲を有名人に絞る案は `Which famous person would you like to be for one week?` である。

名指しが好意的に働く卓もあり、作者が開示されることの重さは卓の関係性で変わる。

変更後の `q_instant_skill` は、日常の `q_superpower`（ささやかな超能力）と答えが近づく可能性がある。
超能力は現実にない力、技能は練習で身につく力という違いがあるが、卓で区別されるかは未検証である。

## レビューの限界

* **観点ごとに独立した複数体のレビューを経ていない**。作成時の自己点検と独立レビューは、どちらも1体のAIが全観点を順に当てたものであり、観点間で判断が割れる機会がなかった。日常の記録と同じ確からしさではない
* 独立レビューのAIは作成AIと同じモデルである。モデルに共通する判断の偏りは、独立レビューでも打ち消されていない可能性がある
* すべて推論である。収束の見積り、発想の負荷、面白さの見込みはいずれも計測値ではない
* ネイティブ話者による英文の確認を経ていない。`hintEn` の枠の前後が文として成立するかは、AI2体の判断だけである
* 卓の構成が不明。参加者どうしの関係性によって、`q_swap_lives` の論点の重さが変わる
* 画面での見え方を確認していない。このパックをロビーで選び、`briefing` と `writing` で枠が表示されるところは実機で確かめていない
