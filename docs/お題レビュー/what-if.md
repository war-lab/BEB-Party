## パックの骨格

| 項目 | 内容 |
| --- | --- |
| 質問 | 12件（検証2の下限4件に対して8件の余裕。1ゲームで2問使う） |
| 言い回しの例 | 1問3件、すべて空欄（`...`）を含む枠（検証6、検証10） |
| 指名用の言い回し | 9件（検証8の下限3件に対して6件の余裕。断定4件、質問2件、否定1件、その他2件） |
| 質問の型 | すべて仮定を語るもの。変身と入れ替わり3件（動物、人生の交換、クローン）、お金と暮らし3件（100万円、お店、住む場所）、創作3件（祝日、映画の題名、しゃべる持ち物）、人と能力3件（食事の相手、一晩で身につける技能、10歳の自分） |

テーマは「仮定の質問」とした。
[日常](./daily.md) にも仮定の質問が6件ある（最後の食事、博物館、超能力、無人島、タイムマシン、家のルール）。
このパックではそれらと同じ題材を避けた。

超能力と近い「透明人間になったら」、最後の食事と近い「一生ひとつしか食べられないなら」は候補から外した。

仮定の質問は、事実を問う質問より答えの幅が広く、書き手の好みと価値観が出やすい。
一方で、答えを作る負荷が経験の想起ではなく発想にかかるため、思いつかない参加者が止まる危険がある。
その対処として、1件目の `hintEn` は質問文の動詞をそのまま受ける形にした。

指名用の言い回しには、仮定のテーマに合わせて `Aya would choose that.`（その人が選びそうだという根拠）と `Would you really do that?`（本当にそうするかを問う）を入れた。
性別代名詞は使わず、名前の型にした（日常と同じ方針）。

## クロスレビュー（未実施）

### 実施した点検

複数観点のクロスレビューは実施していない。
作成したAIエージェント1体（モデル: Claude Opus 5.5）が、[日常](./daily.md) のクロスレビューで使った3観点を1人で順に当てて自己点検した。

観点どうしの独立性はない。
1人の判断であるため、日常の記録にあるような観点間の衝突と裁定は起きていない。

| 観点 | 点検した内容 |
| --- | --- |
| A | 回答の分散と作者当ての成立性 |
| B | 英語の質と難度適合 |
| C | 場の安全性とパーティゲームとしての面白さ |

### 観点Aの点検（回答の分散）

12件とも、答えが書き手の好みで決まる質問である。
知識を問う質問は入れていない。

収束が起きやすいと見積った質問は次の3件である。

* `q_million_yen`: 旅行や貯金へ寄る可能性がある
* `q_live_anywhere`: ハワイなど定番の地名へ寄る可能性がある
* `q_clone`: 「仕事をさせる」へ寄る可能性がある

いずれも、続く語（誰と、なぜ、何の仕事を）で1文全体には差が出ると判断し、収録した。
見積りであり、実測していない。

`q_movie_title` と `q_talking_object` は、創作を求めるため収束が最も起きにくいと見込んだ。

### 観点Bの点検（英語の質と難度）

12件のうち8件が `If ..., what would ...?` の仮定法の文である。
仮定法過去（`If you could`、`If your life were`）はレベル1〜2には読みにくい可能性がある。
`ja` を全件「〜なら、〜？」の形にして、条件と問いを取り違えないようにした。

`hintEn` は1件目が最も平易になるよう並べた。
1件目は `I would be a ... for a day.` や `I would live in ...` のように、質問文の `would` をそのまま受ける形にした。
レベル3以上には1件目だけが配られるため、1件目だけで答えの骨格が作れるようにしている。

`q_younger_self` の1件目 `Do not worry about ...` は、10歳の自分へ直接語りかける命令文である。
`I would tell myself to ...` を1件目にしなかったのは、`tell myself to` の構文が命令文より難しいと判断したためである。

`q_swap_lives` の2件目 `I want to try ...'s life.` は、空欄の直後に所有格の `'s` が付く。
空欄へ名前を入れれば成立するが、`...` ごと写した場合は読みにくい文になる。
枠として成立しており、検証10の目的（完成文を配らない）には反しない。

### 観点Cの点検（場の安全性と面白さ）

家庭環境に依存する質問を避けた。
`q_million_yen` の3件目は、家族を前提にしないよう `I would give half of it to ...` とした。

注意を要する質問は次の2件である。

* `q_swap_lives`: 同室の参加者の名前を書くことができる。好意的な文脈になる見込みだが、特定の参加者をからかう答えが出る可能性はある
* `q_dinner_anyone`: 亡くなった人を挙げる参加者がいる可能性がある。英語圏の定番の質問（`living or dead`）の形は避け、範囲を示さない文にした

いずれも、作者が `judging` で開示される点は日常と同じである。
隠し通しの1点が、無難な答えを書く動機として働く見込みもある。

面白さの見込みが高いのは `q_movie_title`（人生の映画の題名）、`q_talking_object`（しゃべる持ち物）、`q_new_holiday`（新しい祝日）である。
答えの意外さに書き手の個性が出やすい。

## 確定した変更

初版であり、変更前後の記録はない。
自己点検の過程で、作成中に次の判断をした。

| 対象 | 判断 | 理由 |
| --- | --- | --- |
| 候補「透明人間になったら」 | 不採用 | 日常の `q_superpower` と題材が重なる |
| 候補「一生ひとつしか食べられないなら」 | 不採用 | 日常の `q_last_meal` と題材が重なる |
| 候補「明日が急に休みになったら」 | 不採用 | 日常の記録で差し替えた `q_free_day` と同じ理由（寝るへの収束、休みがない層） |
| 候補「どんな言語でもすぐ話せるなら」 | 不採用、`q_instant_skill` へ統合 | 技能の質問と重なる。英語へ収束しうる |
| 候補「世界に1つルールを作るなら」 | 不採用 | 日常の `q_house_rule` と題材が重なる |

## 未解決の論点

| 論点 | 内容 |
| --- | --- |
| 回答の収束 | `q_million_yen`、`q_live_anywhere`、`q_clone` の定番解への収束は見積りであり、未実測である |
| 発想の負荷 | 仮定の質問は、答えを作る負荷が発想にかかる。`q_movie_title` と `q_new_holiday` で思いつかない参加者が止まるかは未検証 |
| 仮定法の読解 | 8件の `If ..., what would ...?` を、レベル1〜2が `ja` なしで読めるかは未検証 |
| 同室の参加者への言及 | `q_swap_lives` で同室の参加者を名指しした答えが、場の空気をどう変えるかは未検証 |
| 質問の再登場 | 同じ部屋で続けて遊ぶと同じ質問を引きうる（[基本設計/11](../基本設計/11_WHOWROTETHISゲームモジュール.md) の未解決の論点） |

## レビューの限界

* **独立した複数観点のレビューを経ていない**。3観点を1体のAIが順に当てたものであり、観点間で判断が割れる機会がなかった。日常の記録と同じ確からしさではない
* すべて推論である。収束の見積り、発想の負荷、面白さの見込みはいずれも計測値ではない
* ネイティブ話者による英文の確認を経ていない。特に `hintEn` の枠の前後が文として成立するかは、作成AIの判断だけである
* 卓の構成が不明。参加者どうしの関係性によって、`q_swap_lives` の論点の重さが変わる
* 画面での見え方を確認していない。このパックをロビーで選び、`briefing` と `writing` で枠が表示されるところは実機で確かめていない
