# お題レビュー: SECRET RULE ENGLISH「はじめての規則」

## 結論

`content/secretrule/basic.json`（規則の候補10件、規則IDごとの言い回し10種、報告と相談の言い回し13件、書き出しの例4件）と、検証用の文例集 `content/secretrule/corpus/sentences.json`（100件）、画面と遊び方に出る英語と日本語の収録時レビューの記録である。

水準は**AIによる4観点のクロスレビュー1巡**であり、実際の参加者による確認は行っていない。

この巡で最も重い欠陥は、文例集をパックに合わせて作っていたことである。
初版の文例集97件のうち末尾32件は、初版の候補を検証に通すために書き足した文であり、前半65件だけで測ると検証6の範囲外が2件、検証7の不足が11組出た。
設計が警告していた「パックに寄せた文例集で検証を通す」ことを、収録の作業そのものが行っていた。

文例集は、パックと判定関数と設計文書を読ませない書き手に100件を書き直させて置き換えた。
その上で候補の母集団を測り直し、自然な英文での通過率が範囲を外れる候補（`no_e`、`colors`）と、英文で見分けられない組を作る候補（`no_i`）を外して、候補10件を選び直した。

ほかに、規則の文と判定の食い違い（ハイフン語、末尾の記号、先頭の記号）、回答の合意に使う言い回しの欠落、書き出しの例の偏り、案内文の誤解を招く表現を直した。

## セットの骨格

| 項目 | 内容 |
| --- | --- |
| 候補の母集団 | 10件。`question`（? で終える）、`no_n`（n を使わない）、`max5`（5語以下）、`min8`（8語以上）、`long8`（8文字以上の語を使う）、`the`（the を使う）、`time_words`（時を表す語10語のどれかを使う）、`has_f`（f を使う）、`no_h`（h を使わない）、`start_i`（i で始まる語から書き始める） |
| 規則IDごとの言い回し | 10種（en と ja）。候補で使わない `no_word` と `short_words` も持つ |
| 報告と相談の言い回し | 13件。成否の報告、聞き返し、試す英文の提案、仮説の提案、候補の除外、回答の合意の型 |
| 書き出しの例 | 4件。疑問文1件、7語以上の文1件を含む |
| 文例集 | 100件。疑問文19件、感嘆文11件、語数3〜5が35件、6〜9が35件、10以上が30件 |

## 機械検証の結果

| 検証 | 結果 |
| --- | --- |
| `pnpm validate:content`（12項目） | PASS（警告1件: `no_n` を満たし `max5` を満たさない文の割合が7.0%で、閾値5%に近い） |
| サーバのユニットテスト | PASS（70件） |
| 通しE2E（2人・4人） | PASS（各3回の繰り返しを含む） |

候補ごとの文例集での通過率は次のとおりである。

| 候補 | 通過率 |
| --- | --- |
| `question` | 19% |
| `no_n` | 23% |
| `time_words` | 25% |
| `the` | 27% |
| `no_h` | 29% |
| `has_f` | 34% |
| `max5` | 35% |
| `long8` | 42% |
| `start_i` | 42% |
| `min8` | 43% |

全90の順序対で、分離の割合の最小は7.0%（`no_n` > `max5`）であり、それ以外は8%以上である。

**言い回しと判定関数の意味の一致を確かめる検査は無い。**
E2Eは、候補idをキーにした判定の写し（`e2e/support/secretrule.ts`）で規則を絞っており、候補の英文を読んでいない。
英文がコードと違う条件を述べていても、機械検証とE2Eはすべて通る。

E2Eの判定の写しは `rules.ts` を写したものであり、`rules.ts` 自体の誤りは検出できない。
判定関数の境界はユニットテスト（`rules.test.ts`）で固定している。

成否が書いた本人の画面にだけ出ることは、モジュールのユニットテスト（遷移ごとに作者以外の秘密と公開状態を検査）と、E2Eの `state` の走査（`"passed"` が載らないこと）で担保している。
他人の英文の行に成否が出ないことを、E2EはDOMで明示的には検査していない。

### 文例集の書き直しと候補の選び直し

書き直しでは、書き手に `content/secretrule/`、`server/games/secretrule/`、`docs/` を読ませなかった。
指示したのは、話題の分散、疑問文と感嘆文のおよその件数、語数の帯ごとのおよその件数、作為的な文を書かないことだけである。

書き直した文例集の上で、規則IDとパラメータの組を広く測った。
自然な英文では、`no_e`（e を使わない）と `colors`（色の語を使う）の通過率が15%を割った。
`no_i`（I を使わない）は、「? で終わり I を含む文」が文例集に無く、`question` と見分けられなかった。

この3件を外し、範囲内に入った組から規則IDが偏らないように候補10件を選んだ。
文例集には手を加えていない。

## 未解決の論点

* 卓が `I'm` を `I` と別の語として、`black-and-white` を1語として扱えるか
* 実際の卓の英文で、候補の通過率が15〜70%に入るか
* 報告と合意の言い回しが実際に使われるか
* `proving` の避ける候補を、補足の文があっても読み誤らないか
* 画面を見せ合ってしまわないか

## レビューの限界

* 文例集は別の書き手が書いたが、書き手も評価者も同じモデル系統のAIである。卓の英文の代わりとして妥当かの判断は推定であり、実際の学習者の英文で確かめていない
* 語彙の難度とレベル適合はAIの推定であり、学習者での確認ではない
* 4体とも同じモデルであり、同じ見落としを共有している可能性がある（[room.md](./room.md) と同じ限界）
