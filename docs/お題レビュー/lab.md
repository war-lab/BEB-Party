# お題レビュー: ESCAPE CALL「深夜の研究所」

## 結論

`content/escapecall/lab.json`（規則5種の言い回し15文、質問と確認の言い回し、舞台の文言）と、画面・遊び方に出る英語の収録後レビューの記録である。

水準は**AIによる4観点のクロスレビュー1巡**であり、実際の参加者による確認は行っていない。

機械検証（検証10項目）は収録時点でPASSしていた。
この巡で見つかった欠陥はすべて「機械で検査しないもの」の側にあった（[基本設計/13](../基本設計/13_ESCAPECALLゲームモジュール.md)）。

答えを取り違える経路が2件あり、どちらも英文を直した。
`swap_ends` が何の最初と最後かを言っておらず、錠3で除く規則と組むと誤答の経路ができていた。
`add_one` の「9は0」は、足した後の9を0にするとも読めた。

ほかに、`standard` が `easy` の言い換えにとどまって設計（条件を含む文）と一致していなかったこと、解錠中に言い回しを見返せなかったこと、遊び方が数字の規則を説明できていなかったことを直した。

2人卓で規則が口に出ないこと、聞き手のレベルと `standard` の関係は、実プレイを見てから決める論点として残した。

## セットの骨格

| 項目 | 内容 |
| --- | --- |
| 規則の言い回し | 5規則 × 3文（`easy` / `standard` / `ja`）。`easy` はレベル1〜2の規則を持つ人へ日本語の補足つきで、`standard` は3〜5へ配る |
| 質問と確認の言い回し | 11件（全員へ公開。作戦会議と解錠中の早見表に出る）。この巡で6件から増やした |

| 色と形の名前 | コードに持つ（`shared/games/escapecall/src/symbols.ts`）。規則の文の `{color}` / `{shape}` と早見表に入る |

## 機械検証の結果

| 検証 | 結果 |
| --- | --- |
| `pnpm validate:content`（10項目） | PASS（0件の警告） |
| 生成の性質テスト（1000件のseed × 2〜4人） | PASS |

**英文と規則IDの意味の一致を確かめる検査は無い。**
E2Eと撮影は、画面の `data-rule-id` と `data-param` から答えを計算しており、英文を読んでいない。
英文がコードと違う作用を述べていても、機械検証とE2Eはすべて通る。

この巡の指摘のうち、機械の検査に落とせたものは無い。
いずれも英文の意味の読み方に関するものであり、文字列の照合では判定できない。

## クロスレビュー

実施主体はAI（Claude Opus 5.5）である。4体を独立に走らせ、互いの結論を見せずに報告させた。

| 観点 | 担当 |
| --- | --- |
| A | 規則文と作用の一致（英文がコードの作用と同じ意味に読めるか。錠3で2つの規則を続けて読んだときに適用順を取り違えないか） |
| B | レベル適合（`easy` がレベル1〜2に通じるか、`standard` が難度として機能しているか、画面の英語） |
| C | 口頭で伝わるか（色と形の語の聞き違い、言い回しの過不足、4人卓の前半・後半の受け渡し、場の安全性） |
| D | 前提検証（レビューの範囲と問いの妥当性。英文の中身は渡さず、目的と問いだけを渡した） |

1体だけが挙げた指摘は、一次情報（コード・画面の実装）を読んで確かめてから採った。

### 2観点が独立に挙げた欠陥

| 対象 | 指摘 | 観点 |
| --- | --- | --- |
| `swap_ends` の範囲 | 何の最初と最後かを言っていない。錠3で除く規則と組むと誤答の経路ができる（表の下に詳述） | A・D |
| `standard` の難度 | 5文とも `easy` の語を入れ替えただけで、設計の「条件を含む文」と一致していなかった。特に `swap_ends` の "Switch the first number with the last one." は `easy` と難度が同じだった | B・D |
| `reverse` の "it" | "Read it from right to left." の "it" が文の中で何も指していない。答えへの影響は無い | A・D |
| 答える側の言い回しが無い | 言い回しが質問だけで、並びを持つ人・数字の表を持つ人が答える形の見本が無かった | B・C |

`swap_ends` の英文 "Swap the first and last numbers." は、何の最初と最後かを言っていなかった。
除かれる記号にも対応表の数字がある（`lock.ts` の対応表は並びの全記号を含む）。
そのため「並び全体を数字にして両端を入れ替えてから除く」読み方でも計算が最後まで進み、誤答になる。

Aの計算では、除く記号2個の位置の全21通りのうち11通りで答えが変わる（位置の分布は一様と仮定した。実分布は計測していない）。

`reverse` の "it" は、3〜4人卓で問題になる。規則を持つ人は並びを持たないため、口頭で1文だけ伝えると指す先が共有されない。
記号の逆順と数字の逆順は同じ結果になるため、答えは変わらない。

### 1観点が挙げ、一次情報で確かめて採った指摘

| `blue` / `black` の聞き違い | 対応表に同じ形の別の色がある場合、聞き違えても「持っていない」にならず別の数字が返る。設計の「形で絞れる」は条件付きでしか成り立たない | C | 対応表が6〜8種を持つこと（`LOCK_SPECS`）と、`blue` / `black` の語頭が同じことを確かめた |

| 数字の表の「（前半）」 | 数字の表は順序を持たないのに「（前半）」と出ており、先に話す人と誤読される | C | `PieceView.svelte` を確かめた |

### 残した論点（直さずに記録した）

| 対象 | 指摘 | 観点 | 残した理由 |
| --- | --- | --- | --- |
| 2人卓で規則が口に出ない | 2人卓では並びと規則を同じ人が持つ。規則を英語で伝える工程が起きず、低い方は3つの錠すべてで「2語を聞いて数字を言う」だけになる | B | 断片の割り当ての変更は設計判断であり、英文レビューの範囲を超える。実プレイで単調かどうかを見てから決める（基本設計13の未解決の論点に追記） |
| 聞き手のレベルと `standard` | 段は規則を持つ人のレベルで決まり、通常はレベル3以上の人に `standard` が出る。そのまま読み上げるとレベル1の聞き手に届かない可能性がある | D | 遊び方に「言い換えてよい」と書いた。言い換えの例を画面に出すかは未決（基本設計13の未解決の論点に追記） |
| 規則を持つ人の役割 | `reverse` / `swap_ends` / `add_one` は1回読み上げると終わり、規則を持つ人が見ているだけになる可能性がある | C | 遊びとしての質の問題であり、実プレイで確かめる |
| `reverse` と `swap_ends` の組 | 逆順の後に両端を入れ替えると、両端が元の位置に戻る。遊ぶ人が「規則が効いていない」と感じる可能性がある | A | 答えは正しい。気になれば生成の組み合わせ制約で外す |
| `five` / `nine` の聞き違い | 騒がしい場で紛れやすい組 | C | 確認の言い回し（"Let me check. Is it ..."）で拾う |
| 公開状態に前半・後半を載せる | だれが並びの前半を持つか、他の人に分からない | C | 公開状態の型を変える変更になる。言い回し（"Who has the first half?"）で吸収した |

### 却下した問い

Dの指摘を受け、次の問いは判別力が無い、または決定済みの事項を再評価するものとして評価から外した。

* 遊びとして成立するか: AIがどちらと答えても、次の行動は実プレイで確かめることで変わらない
* 900点台に合っているか: 段は2つしかなく、段を増やすのは設計の変更になる
* 色4種・規則5種・段の切り替えの是非: 基本設計13と [ADR-0027](../adr/0027-ESCAPECALLの謎はテンプレートとseedから生成する.md) で決定済み
* `easy` を読んで理解できるか: 日本語の補足が必ず付くため判別力が低い。声に出して言えるか・聞き手に伝わるかに置き換えた

## 確定した変更

| 対象 | 変更前 | 変更後 |
| --- | --- | --- |
| `swap_ends` easy | Swap the first and last numbers. | Swap the first and last numbers of the answer. |
| `swap_ends` standard | Switch the first number with the last one. | In the final answer, the first and last numbers change places. |
| `swap_ends` ja | 最初と最後の数字を入れ替える | 答えの最初と最後の数字を入れ替える |
| `add_one` easy | Add one to each number. Nine becomes zero. | Add one to each number. For nine, write zero. |
| `add_one` standard | Make every number one bigger, and turn nine into zero. | Each number goes up by one. If a number is nine, it goes back to zero. |
| `add_one` ja | すべての数字に1を足す（9は0にする） | すべての数字に1を足す（9のときは0と書く） |
| `reverse` easy | Read it from right to left. | Read the symbols from right to left. |
| `reverse` standard | Read the row backwards, starting from the right end. | Start with the last symbol and finish with the first one. |
| `reverse` ja | 右から左へ読む | 記号を右から左へ読む |
| `skip_color` standard | Ignore every {color} symbol when you read the row. | Read only the symbols that are not {color}. |
| `skip_shape` standard | Leave out every {shape} when you read the row. | If a symbol is a {shape}, do not use it. |
| 言い回し | 6件（質問と確認のみ） | 11件。答える形（The first one is a blue circle. / The red star is three.）、確認（Blue or black?）、規則と前半を尋ねる形を追加 |
| 導入文 | The power went out and every door locked. | The lights are off. All the doors are locked. |
| 色名（日本語） | 黄 | 黄色 |
| 解錠の画面 | 早見表は色と形だけ | 早見表に言い回しも出す |
| 断片の見出し | 読み方の規則（上から順に） | 規則（上から順に使う） |
| 数字の表の分割表示 | （前半）／（後半） | （半分） |
| 後半の並びの注記 | 前半を持つ人の続きです。 | 何番目かを付けて言う見本（The third one is ...）を追加 |
| ふりかえり | TIME UP、錠の名前は英語だけ | TIME'S UP!、錠の名前に日本語を併記 |
| 遊び方 | 「並びを規則のとおりに読む」 | 並びに使う規則と、置き換えた後の数字に使う規則を分けて説明。聞き違いの確かめ方、答え方の見本、言い換えてよいことを追加 |
| ムービーの台本 | 読み方の指示を英語で伝える | 答えの作り方を英語で伝える |

`standard` の書き換えでは、条件（that are not / If a symbol is）や否定（do not use）を入れ、`easy` との差を語彙ではなく文の読み取りに置いた。
`swap_ends` と `add_one` は、範囲（of the answer / In the final answer）と対象（For nine / If a number is nine）を明示し、錠3で規則を2つ続けて読んだときに一意に読めるようにした。

## 未解決の論点

* `standard` を条件の文にしたことで、規則を持つ人が言い換える負担が増えた。そのまま読み上げた場合に聞き手へ届くかは実プレイで確かめる
* 追加した言い回し（Blue or black? など）が実際の場で使われるか
* 2人卓の割り当て（上の「残した論点」）

## レビューの限界

* 日本人学習者が `blue` と `black`、`five` と `nine` を、騒がしい同室の環境で聞き分けられるかは確かめていない
* 濃紺の黒（`#161B33`）を実際の画面で `black` と呼ぶか、`blue` や `navy` と呼ぶかは確かめていない
* レベル1〜2の人が `easy` の英文を声に出して言えるか、レベル1の聞き手が `standard` の読み上げを聞き取れるかは確かめていない
* 規則を持つ人が実際に読み上げるのか、言い換えるのか。言い換えたときに意味が保たれるかは確かめていない
* 語彙の難度（中学何年の範囲か）はAIの推定であり、学習者での確認ではない
* 4体とも同じモデルであり、同じ見落としを共有している可能性がある（[room.md](./room.md) と同じ限界）
