# お題レビュー: BLIND ROOM「公園」

## 結論

`content/blindroom/park.json`（アイテム20件と言い回し18件）の収録前レビューの記録である。

水準は**AI（Claude Opus 5.5）による作成時の自己点検1巡と、作成者とは別に起動したAIによるクロスレビュー1巡**である。
実際の参加者による確認は行っていない。

機械検証（検証13項目）と、アイコンの検査7項目はPASSした。
機械で検査しない項目のうち、絵と英語名の一致と44pxでの取り違えは、生成したSVGを画像にして目視で確かめた。

クロスレビューでは色覚特性（2型と1型）の近似表示も加えて見直し、直すべき点は見つからなかった。
この目視はいずれもAIが行ったものであり、人の目では確かめていない。

未解決の論点は、`standard` の色ペアが見本に出ないラウンドと、言い回しの実用性である（「未解決の論点」）。

## セットの骨格

| 項目 | 内容 |
| --- | --- |
| アイテム（easy） | 10件、1語、すべて違う形。tree / bench / bird / kite / flower / balloon / umbrella / slide / bucket / bike |
| アイテム（standard） | 10件、2語。5つの形（kite / balloon / umbrella / bucket / bench）× 赤と青 |
| 説明者の言い回し | easy 7件、standard 5件（レベル1〜2へ先頭4件、3〜5へ先頭2件を配る） |
| 聞き手の言い回し | 6件（全員へ公開） |
| アイコン | 新しい形状10種から作る20点のSVG。`client/public/items/blindroom/` |

テーマは「部屋のもの」と重ならないように、屋外の公園で見るものに揃えた。
`room` と同じ語（ball / chair / lamp 等）は使っていない。

`standard` は `room` と同じく「5つの形 × 2色」とした。
パレットには常にセット全10件が並ぶため、見本に赤しか出ないラウンドでも `kite` だけでは指せない。

色はすべて無生物（凧、風船、傘、バケツ、ベンチ）に付けた。
`room` のレビューで残した「色を人や動物に載せない」指針に従うためである。
easy の `bird` は青で描いたが、easy は名前で指すセットであり、色を言う必要はない。

## クロスレビュー

作成時の自己点検の後に、作成者とは別に起動したAI（Claude Opus 5.5）が1巡レビューした。
作成時の会話は引き継がず、パック、形状の定義、基本設計12、ADR-0025、本記録と `room` の記録を読んで行った。
作成者と同じモデルであるため、モデル固有の見落としは共有されている可能性がある。

### 観点

| # | 観点 |
| --- | --- |
| 1 | 各アイコンが英語名どおりに見えるか。44pxと32pxで同じセットの他と取り違えないか。standard の赤青が色だけで言い分けられるか |
| 2 | `en` と `describerHints` と `keyExpressions` が自然な英語か。盤面の広さによらず成立するか。先頭ほど平易か |
| 3 | `ja` の訳が絵と `en` に合っているか |
| 4 | easy の10件が名前だけで区別でき、英語で説明しやすいか。`room` と重複しないか |

### 絵の確認の方法（クロスレビュー）

作成時と同じく、Playwright（Chromium）で1枚のシートに並べて撮影し、その画像を見た。
シートの作成スクリプトは作業用であり、リポジトリには置いていない。

* 各セットの10点を、1マス85px、1マス44px、パレットのチップと同じ32pxの3段で並べた
* 同じ10点を44pxで、2型と1型の近似（色行列による簡易な模擬）と、グレースケールで並べた
* マスの地、枠、アイコンの大きさ（マスの85%）は作成時と同じにした

### 指摘と判断

| # | 対象 | 指摘 | 判断 |
| --- | --- | --- | --- |
| 1 | easy の10点 | 85px、44px、32pxのいずれでも、名前どおりに見え、互いに取り違える組は見当たらなかった | 変更しない |
| 2 | `tree` | 緑を使えないため樹冠が黄であり、秋の木に見える。形は木として読める | 変更しない。色は easy では判定に関わらない |
| 3 | standard の赤青 | 5組とも44pxと32pxで見分けられた。2型と1型の近似でも、赤は黄みに、青は青紫に寄り、組の中で分かれた | 変更しない |
| 4 | standard の赤青（グレースケール） | 赤と青の明度が近く、グレースケールでは組の区別が付かない | 変更しない。`room` と同じ5色であり、ADR-0025 が想定する色覚特性（2型と1型）の範囲外である。論点に足した |
| 5 | 英文 | `en` 20件、`describerHints` 12件、`keyExpressions` 6件に不自然な英語は無かった。先頭2件は `room` と同じ枠であり、4列でも4段でも成立する | 変更しない |
| 6 | `Is it on the left side or the right side?` | 3列の中央列にあるとき答えが選択肢に無い（作成時の論点）。ただし `It's in the middle.` はレベル1〜2でも言える短い応答である | 変更しない。作成時の論点のまま残す |
| 7 | `ja` | 20件とも絵と `en` に合っている | 変更しない |
| 8 | easy の名前 | 10件とも意味の離れた名詞で、名前だけで区別できる。`room` の20件とも語と絵が重ならない | 変更しない |
| 9 | `bucket` | 85pxでは取っ手の弧が縁と重なり、上に少し出るだけである。44pxでもバケツと読めるが、植木鉢やごみ箱と言い換える参加者がいる可能性がある | 変更しない。論点に足した |

### 絵の確認の方法（作成時）

生成したSVGを、Playwright（Chromium）で1枚のコンタクトシートに並べて撮影し、その画像を見て確かめた。

* マスの地は盤面と同じ `#f7f8fd`、枠は盤面と同じ半透明の2px線にした
* 各セットの10点を、見本と同じ1マス85pxと、開示と同じ1マス44pxの2段で並べた
* アイコンはマスの85%の大きさで描いた（`BoardGrid.svelte` と同じ）

シートの作成スクリプトは作業用であり、リポジトリには置いていない。

### 確認した項目と結果（作成時）

| 項目 | 結果 |
| --- | --- |
| 絵が英語名どおりに見えるか | 初版では `tree` が、平らな樹冠の下端と太い幹のため、44pxできのこに見えた。描き直した後は10点とも名前どおりに見えると判断した |
| easy の10点を44pxで取り違えないか | 取り違えの候補は見当たらなかった。`kite` と `balloon` はどちらも尻尾が下に垂れるが、ひし形と楕円で輪郭が違う |
| standard の赤青を44pxで見分けられるか | 5組とも、着色した面が絵の大半を占めるため見分けられた |
| standard の5つの形を44pxで取り違えないか | 取り違えの候補は見当たらなかった |

`umbrella`（easy）は黒で塗った。
黒の傘は輪郭線と塗りが同じ色になるが、シルエットで傘と分かるため採った。

### 言い回しの点検

`describerHints` の先頭2件は `room` と同じ枠にした。
`room` の4巡目で、どの盤面の広さでも使える組として決めた枠であり、テーマに依存しない。

| # | 枠 | 役割 |
| --- | --- | --- |
| 1 | `Put the ... in the ... row, on the ... side.` | 絶対位置（左右の列） |
| 2 | `Put the ... in the ... row, ... from the left.` | 絶対位置（数える） |
| 3 | `The ... is next to the ...` | 相対位置 |
| 4 | `Yes, it is next to the ...` | 質問への応答 |

レベル1〜2へ届く4件は「絶対位置2件、相対1件、応答1件」であり、`room` と同じ配分である。

`standard` の4件目は `No, the blue one is above the ...` とし、`room` の `Yes, the red one is under the ...` と否定と上下を入れ替えた。
聞き手が色を取り違えたときに訂正する型である。
ただしこの枠はレベル3〜5には届かない（先頭2件だけが届く）。

`keyExpressions` には `room` の5件に加えて `Is it on the left side or the right side?` を入れた。
聞き逃したときに、段より先に左右を確かめられるようにするためである。

## 確定した変更

| 対象 | 変更前 | 変更後 | 理由 |
| --- | --- | --- | --- |
| `tree` の形状 | 下端が平らな樹冠と太い幹 | 下端も波打つ樹冠、細い2本線の幹と枝 | 44pxできのこに見えた |

## 未解決の論点

| 論点 | 内容 |
| --- | --- |
| standardの色ペアが出ないラウンド | 見本5個に同じ形の赤青が1組も入らない確率は12.7%（252通り中32通り）である。`room` と同じ構造であり、同じ確率になる |
| 左右を問う質問の答え | `Is it on the left side or the right side?` は、3列の盤面で中央列にあるとき、どちらでもない。`No, it is in the middle.` と答える型は `describerHints` に無い |
| 届かない枠 | easy の5〜7件目と standard の3〜5件目は、どのレベルにも配られない。`room` と同じ構造である |
| 語の知名度 | `kite` `bucket` `slide` がレベル1〜2の参加者に通じるかは確かめていない。`ja` を併記するため聞き手は回復できるが、説明者の画面には `en` が出ない |
| `bike` と `bicycle` | 参加者が `bicycle` と言っても同じものを指せる。照合はアイテムIDで行うため採点には影響しないが、パレットの表記と発話が食い違う |
| グレースケールでの赤青 | standard の赤青は明度が近く、色の手がかりを持たない参加者（1色覚等）には区別できない。`room` と同じであり、5色の選定（ADR-0025）で扱う範囲の外にある |
| `bucket` の言い換え | 取っ手が小さいため、参加者が `pot` や `trash can` と言う可能性がある。パレットの `en` を見れば回復できるため、採点への影響は小さいと見ている（**未検証**） |

## レビューの限界

* 実際の参加者による確認をしていない。「英語で説明したくなるか」「75秒で置けるか」は実プレイでしか分からない
* 絵の確認は、AIがPC上のChromiumで撮った画像を見て行った。スマートフォンの実機、人の目、実際の視距離では見ていない
* クロスレビューは作成者とは別に起動したAIが1巡行ったが、作成者と同じモデル（Claude Opus 5.5）である。観点を分けた複数体のレビューはしておらず、モデル固有の見落としは残っている可能性がある
* 色覚特性の確認は色行列による簡易な近似であり、当事者の目では見ていない
* 既存作品との造形の一致は、幾何形状の自作であることを根拠に「該当なし」と判断した。図案を1件ずつ第三者と突き合わせてはいない
* フォントのサブセット（`fonts:generate`）は再生成していない。新しい `ja`（凧、傘、風船 等）の字形がサブセットに含まれるかは**未検証**である
