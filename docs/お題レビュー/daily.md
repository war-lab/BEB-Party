## パックの骨格

| 項目 | 内容 |
| --- | --- |
| 質問 | 12件（検証2の下限4件に対して8件の余裕。1ゲームで2問使う） |

| 指名用の言い回し | 6件（検証8の下限3件に対して3件の余裕） |
| 質問の型 | 選択を語るもの8件（最後の食事・美術館・超能力・島・タイムマシン・家の決まり・失くす物・日曜） / 経験を語るもの4件（月曜の朝・職場の嘘・二度としないこと・ひどい助言） |

「答えが一意に決まらないこと」を最優先に選んだ。
知識を問う質問（首都・年号）を1件も入れていないのは、全員が同じ英文を書くと作者当てが成立しないためである。

## 自己点検（機械で検査しない5項目）

[基本設計/11](../基本設計/11_WHOWROTETHISゲームモジュール.md) が人手に委ねた項目について、確認した内容と根拠を置く。

| 項目 | 確認内容 |
| --- | --- |
| 回答が1文で書けるか | 12件すべて、`hintEn` の3件が4〜7語の1文で答えの型を示している。型に語を差し替えるだけで成立する |
| 答えが一意に決まらないか | 知識を問う質問を入れていない。最も収束しうるのは `q_monday`（月曜の朝）で、coffee が集まる可能性がある |
| 卓の全員が答えを持てるか | 家庭環境・収入・交際関係を尋ねる質問を入れていない。`q_lie`（職場の嘘）は就業していない参加者には答えにくい |
| 個人情報を尋ねていないか | 住所・年齢・勤務先・家族構成を尋ねる質問はない。`q_never_again` は失敗談を促すため、答えたくない参加者は無害な内容で答えられる余地を残している |
| 英文が自然か | `hintEn` と `keyExpressions` は現在形・単純な語彙で書いた。ネイティブによる確認は経ていない |

確認主体はAIであり、実際の参加者による確認とは別物である。
