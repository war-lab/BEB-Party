# お題レビュー: BLIND ROOM「部屋のもの」

## 結論

`content/blindroom/room.json`（アイテム20件・言い回し16件）の収録前レビューの記録である。

水準は**AIによる3観点クロスレビュー1巡**であり、実際の参加者による確認は行っていない。

レビューの結果、収録を一度止めた。
初版は盤面のアイテムを絵文字で描いており、`standard` セットの5組中4組で「名前が主張する属性を絵柄が持たない」状態だった。
アイテムの絵を自作のSVGへ替え（[ADR-0025](../adr/0025-盤面アイコンはSVGで持つ.md)）、アイテム構成・説明者の言い回し・聞き手の言い回しをすべて入れ替えて再収録した。

機械検証（検証13項目）は初版でもPASSしていた。
この巡で見つかった欠陥はすべて「機械で検査しないもの」の側にあり、うち3件は新しい検査に落とした。

## セットの骨格

| 項目 | 内容 |
| --- | --- |
| アイテム（easy） | 10件・1語・すべて違う形。cat / dog / book / cup / key / clock / lamp / chair / plant / ball |
| アイテム（standard） | 10件・2語。5つの形（book / cup / ball / chair / lamp）× red・blue |
| 説明者の言い回し | easy 6件、standard 5件（レベル1〜2へ4件、3〜5へ2件を先頭から配る） |
| 聞き手の言い回し | 5件（全員へ公開） |
| アイコン | 20点のSVG。`client/public/items/blindroom/` |

`standard` を「5つの形 × 2色」にしたのは、色と物の両方を言わないと指せない状態を作るためである。
パレットには常にセット全10件が並ぶため、見本に赤しか出ないラウンドでも `book` では指せない。

## 機械検証の結果

| 検証 | 結果 |
| --- | --- |
| `pnpm validate:content`（13項目） | PASS（0件の警告） |
| `pnpm test`（アイコンの検査7項目） | PASS |

アイコンの検査は本レビューで追加した（[基本設計/12](../基本設計/12_BLINDROOMゲームモジュール.md) の「アイコンの検査」）。

## クロスレビュー

実施主体はAI（Claude Opus 5）である。3体を独立に走らせ、互いの結論を見せずに報告させた。
観点の分担は次のとおり。

| 観点 | 担当 |
| --- | --- |
| A | アイテムの識別性と英語名（絵と `en` が同じものを指すか、小さい表示で判別できるか） |
| B | `standard` の言い分け可能性と説明の成立性 |
| C | 場の安全性・遊びとしての面白さ・言い回しの実用性 |

### 3観点が独立に挙げた同じ欠陥

AとBが独立に、同じ4組を挙げた。

| 対象 | 指摘 |
| --- | --- |
| `black cat` 🐈 / `white cat` 🐱 | どちらも茶〜橙の猫として描かれる。差は「全身か顔か」であって色ではない。黒猫 🐈‍⬛ はZWJ列であり検証7で落ちるため、この規約下で黒白の動物対は表現できない |
| `big star` 🌟 / `small star` ⭐ | 絵文字は同じemサイズで描かれるため、盤面上に大小差が出ない。差は輝きの装飾のみ |
| `red car` 🚗 / `blue car` 🚙 | Unicodeの名称に色が無い。🚙 の色はベンダー任せで、緑で描かれる実装がある |
| `tall tree` 🌲 / `short tree` 🌳 | 差は針葉樹と広葉樹であり、高低ではない |

いずれも「聞き手の聞き取り能力と無関係に失点する」経路である。
説明者の画面には `en` が出ないため（見本は絵だけを描く）、説明者は絵からどちらが `black cat` かを推測することになる。

### Bが単独で挙げた配分の欠陥

`standard` の `describerHints` は、レベル3〜5へ**先頭2件だけ**が渡る（`hints.slice(0, hintCountFor(level))`）。
初版はその2件が最も見本依存の強い枠だった。

* 1件目 `"The red ... goes above the blue ..."`: 同じ形の赤青が両方とも見本に入っている必要がある。C(10,5)=252通りのうち約42%、上下関係まで求めると約16%
* 2件目 `"The big ... is in the middle of the ... row."`: `big` を持つのは `big_star` だけであり、出現率50%

両方とも使えない見本が24.2%（61/252）だった。
汎用の枠（`"Put the ... one on the left side."` 等）は3件目以降に並んでおり、レベルが高い説明者ほど使えない枠を渡される構造になっていた。

### Cが単独で挙げた欠陥

| 対象 | 指摘 |
| --- | --- |
| `keyExpressions` が配置画面に出ない | 12は「`building` の画面に出す」と定めているが、実装は `briefing` にしか出していなかった。質問が要るのは説明を聞いている最中であり、75秒間そらで覚えている前提は成立しない |
| `"Is it next to the cat?"` | `standard` に `cat` は無く（`black cat` / `white cat`）、`easy` でも猫が盤に出ない確率が50%ある。例文として使えない |
| 位置の汎用質問が無い | 聞き逃したときの第一声（`"Where is the ...?"`）が無く、部分質問3件に分解されていた |
| 速度を要求する言い回しが無い | 聞き返しは `"Say that again, please."` だけで、同じ速度で繰り返されるだけだった |
| 説明者に応答の型が無い | `describerHints` 10件すべてが「伝える」型で、質問に英語で答える型が0件。聞き手側だけ増やしても往復にならない |
| 撤去の操作が画面にない | パレット未選択でマスを押すと確認なしで外れる。5個上限の警告に外し方が書かれていない |
| 「部屋のもの」と中身が合わない | `car` / `tree` / `fish` / `star` は室内のものではない |

### 判断が割れた点

Cは `black cat` / `white cat` について、外国籍の同席者がいる卓で `the black one` / `the white one` という言い方だけが宙に浮く可能性を挙げた（確度は低いと自己申告）。
AとBは同じ2件を、色が描かれていないという別の理由で削除対象としていた。

結果として削除したため判断は割れていないが、**色を人や動物に載せない**という指針として残す。
現在のセットの色はすべて無生物（本・カップ・ボール・いす・ランプ）に付いている。

## 確定した変更

### アイテム

| 変更 | 内容 |
| --- | --- |
| 描画方式 | 絵文字 → 自作SVG（[ADR-0025](../adr/0025-盤面アイコンはSVGで持つ.md)） |
| easy | `car` `tree` `fish` `star` を落とし、`clock` `lamp` `chair` `plant` を入れた（室内のものへ揃えた） |
| standard | 5組すべてを入れ替え、5つの形 × red・blue にした。大小・高低の対比は捨てた |
| 色 | red / blue / yellow / white / black の5色に限定した。緑を使わないのは、色が正解の判定軸であり、赤緑の組が2型・1型色覚で潰れるためである |

### 言い回し

| 変更 | 理由 |
| --- | --- |
| `keyExpressions` を5件とも入れ替え | `"Where is the ...?"` と `"Slowly, please."` を追加。`cat` のベタ書きを `...` の枠にした。`"Left or right?"`（中央が落ちる）と `"Is that square empty?"`（指示対象を共有できない）を落とした |
| `standard` の枠の順序を入れ替え | 汎用の2件（`"The ... is next to the ..."` / `"The ... is in the middle of the ... row."`）を先頭に置き、レベル3〜5へ確実に使える枠が渡るようにした |
| 応答の型を追加 | easyに `"Yes, it is next to the ..."`、standardに `"Yes, the red one is under the ..."` を入れた |
| 画面の注記を修正 | 「`...` はものの名前に置き換えてください」→「`...` は、ものの名前や top・red のような語に置き換えてください」。空欄には位置語や形容詞も入るため、注記どおりに埋めると非文になる枠があった |

### 実装

| 変更 | 理由 |
| --- | --- |
| 配置画面に `keyExpressions` を出した | 12の仕様どおりにした。折りたたみにして画面高を圧迫しないようにした |
| パレットのチップに `ja` を併記した | 語の同定に失敗した聞き手の回復手段が絵だけになっていた |
| 開示の盤面を1マス19px→44pxへ拡大 | 外したマスを自分で確かめられず、採点への納得が得られない |
| 見本のカットインを不透明にした | 開いた後の地が透けており、後ろの得点表と重なって読めなかった |

## 未解決の論点

| 論点 | 内容 |
| --- | --- |
| 撤去操作の分かりにくさ | パレット未選択でマスを押すと外れる仕様を画面で説明していない（Cの指摘）。5個上限の警告文を「もう一度タップで外せます」へ変える案を保留している |
| 説明の文型が反復するか | `standard` は5組すべてが色の対比であり、6ラウンド回すと `"The [色] [物] is [位置]"` に収束する可能性がある（Cの指摘）。状態の対比（open book / closed book 等）を1組入れる案を保留している |
| 44pxでの取り違え | 20点を44pxで並べたコンタクトシートで確認したが、確認したのはPC上の1環境である。実機の画素密度と視距離では未確認 |
| 小さい端末での収まり | 390×844相当で配置画面の文書高は約920px。375×667ではパレット下段と「できた」がスクロールの下に入る |

## レビューの限界

* 実際の参加者による確認をしていない。「英語で説明したくなるか」「75秒で置けるか」は実プレイでしか分からない
* アイコンの判別性はPCのブラウザで確認した。スマートフォンの実機では見ていない
* 3観点はいずれも同じモデル（Claude Opus 5）であり、モデル固有の見落としは共有されている可能性がある
* 既存作品との造形の一致は、幾何形状の自作であることを根拠に「該当なし」と判断した。図案を1件ずつ第三者と突き合わせてはいない
