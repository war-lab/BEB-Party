# お題レビュー

## 結論

収録したお題セットごとに、機械検証の結果・人手レビュー・未解決の論点を1ファイルに記録する。

お題データそのものの正本は `content/<gameId>/*.json` であり、ここは「なぜその形にしたか」と「機械検証が担保しない部分をどう確認したか」の記録である。

DON'T SAY ITの検証項目は、人物の知名度・禁止語の並び順・説明の成立性を機械で見ない（[基本設計/09](../基本設計/09_DONTSAYITゲームモジュール.md)の「機械で検査しないもの」）。
BLIND ROOMは、アイコンの絵と英語名が同じものを指して見えるか、小さい表示で取り違えないかを機械で見ない（[基本設計/12](../基本設計/12_BLINDROOMゲームモジュール.md)）。
この記録がないと、それらを誰が何を根拠に確認したかが残らない。

確認をAIが行った場合は、そのことと限界を記録に明記する。
実際の参加者による確認とは別物であり、混同すると「確認済み」の意味が変わる。

新しいセットを追加したら、同じ節構成の記録をこのディレクトリに置く。

## 記録の書き方

各ファイルは次の節を持つ。

* **結論**: 検証の通過状況、人手レビューの結果、未解決の論点
* **セットの骨格**: 枚数・分野の分布・制約カード・重要表現
* **機械検証の結果**: 検証9項目とリントの通過状況
* **経緯**: 日付と出来事。何巡目に何を変えたかを追えるようにする
* **クロスレビュー**: 実施主体（人かAIか、AIならモデル）、レビュアーの担当、指摘・反論・確定内容。判断が割れた点は割れたまま記録し、どちらを採ったかと理由を書く
* **確定した変更**: カードごとの変更前後
* **未解決の論点**: 実プレイで確かめる項目
* **レビューの限界**: その記録で確かめられなかったこと。実プレイで覆りうる判断

事件データのレビュー（[../事件レビュー/](../事件レビュー/)）と同じ方針で書く。
違いは、DON'T SAY ITには推論の骨格がなく、代わりに「禁止語の並び順」と「参加者が名前を口頭で言えるか」が確認の中心になる点である。

## レビューの水準を記録に書く

セットによってレビューの水準が違う。
複数観点のクロスレビューを経たものと、作成時の自己点検だけのものを、記録の「結論」で区別する。

水準を書かないと、一覧に並んだ時点でどれも同じ確からしさに見える。
自己点検だけのセットは、機械検証が通っていることしか担保されていない。

## レビューの観点を固定する

DON'T SAY ITのクロスレビューは3観点で行う。観点の分担は固定し、記録に明記する。

| 観点 | 担当 |
| --- | --- |
| A | 知名度と参加者適合 |
| B | 説明の成立性と英語の質 |
| C | 場の安全性とパーティゲームとしての面白さ |

観点を固定するのは、巡ごとに担当が変わると「前の巡で誰が何を見たか」が追えなくなるためである。
[famous-figures.md](./famous-figures.md) の1巡目からこの3観点を使っている。

各観点は互いの結論を見ずに独立に評価する。衝突の裁定は全観点の報告が揃ったあとに行う。

同じ成果物を2巡目以降にレビューする場合は、観点の担当は固定したまま**問いを変える**。
1巡目で評価済みの軸（正解の選定・知名度・`ja`・`aliases`）を再評価させても新しい情報が出ない。
2026-09-09の10語化レビューでは、Aを「レベル別の提示数と実効難度」、
Bを「10語にしても1語で即答される経路が残っていないか」、
Cを「機微な語は先頭3語へという規則が書き換え後も守られているか」に振り直した。

## 指摘を検査に落としてから閉じる

レビューで見つけた欠陥は、**語を直して終わらせない**。
その欠陥が機械で判定できる形なら、検査を足してから閉じる。

根拠は実測である。
2026-09-09の10語化レビューでは、3観点が独立に約250件を挙げた。
最大のクラス（同じ概念に2枠、573枚中55枚）は、
検証13を新設して潰したはずの欠陥と同じ性質が別の軸から出たものだった。

前の巡で「11枠を直した」で終わらせたことが原因である。
正しい閉じ方は「そのクラスを検査に落とす」だった。
この巡では検証14〜17を追加し、それが挙げた枠をすべて差し替えた。

検査に落とせない指摘（英語として自然か、その語が実際に発話されるか、
機微な語の判断）は、落とせないことを記録に明記する。

## 指摘されたカードだけ直さない

レビューは実例を挙げるが、網羅ではない。
指摘されたカードだけ直すと、同じ欠陥が挙がらなかったカードに残る。

対処は、指摘から**判定条件を取り出して全数掃引する**ことである。
2026-09-09の巡では、機微な語の指摘が25件だったのに対し、
語彙リストによる573枚の掃引で143件が候補に挙がった。
大半は色や競走の意味での誤検出だったが、掃引しなければ
`Ferdinand Magellan` の `die`@10 と `Captain Cook` の `die there`@9 は残っていた。
