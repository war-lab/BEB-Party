質問と確認の言い回しは、lab.json と同じ11件の型を保ち、例に出す記号と数字だけを変えた。

### 作成時の自己点検

作成時の自己点検は、実施主体がAI（Claude Opus 5.5）1体であり、次の項目を見た。

| 対象 | 確認した内容 | 結果 |
| --- | --- | --- |
| 規則の言い回し | 舞台に合わせて言い換えるか、lab.json の文をそのまま使うか | そのまま使った（下に理由を記す） |
| 質問と確認の例 | 例の記号が `symbols.ts` にある色と形の組か | 赤い四角、青い星。どちらも16種に含まれる |
| 確認の例の数字 | 錠1と錠2の答えの桁数（4桁）と一致し、数字に重複が無いか | 6, 1, 3, 9。4桁で重複は無い |
| `Blue or black?` | 例を変えるか | 変えなかった。lab.md が聞き違えやすい組として追加した確認であり、舞台に依存しない |
| 導入文の締め | before night comes と before it gets dark のどちらにするか | before it gets dark とした。口語でよく使う形であり、日本語も「暗くなる前に」と対応する |
| 錠の名前 | 画面での表示 | 解錠中とふりかえりの両方で日本語を併記する（`Solving.svelte`、`Debrief.svelte`） |

規則の言い回しを lab.json と同じにした理由は次のとおりである。

規則の作用は舞台に依存しない。
記号を除く、並びを逆に読む、答えの両端を入れ替える、数字に1を足す、の5つであり、山小屋でも研究所でも同じである。

lab.md の巡では、`swap_ends` と `add_one` で答えを取り違える経路が2件見つかり、範囲（of the answer）と対象（For nine）を足して直した。
舞台の語（例えば「無線の周波数」「工具の番号」）を文に入れると、何の最初と最後か、何に1を足すかの範囲がまた曖昧になるおそれがある。
舞台の雰囲気は導入文と錠の名前で出せるため、規則の文で出す利点は小さい。

### 収録後レビュー

実施主体は、作成者と独立したAI（Claude Opus 5.5）1体である。
作成時の会話を共有せず、パックと本記録、lab.json と lab.md、基本設計13、ADR-0027、画面のコードを読んで判断した。

観点は次の5つである。

| 観点 | 内容 |
| --- | --- |
| 英文 | `titleEn` と `introEn`、錠の名前、質問と確認の言い回しが自然な英語か。作戦会議の見出しに出る `titleEn` がレベル1〜2に読めるか |
| 訳 | 日本語訳が正確で、英語と意味が一致するか |
| 規則の文と例 | 規則の文を lab.json と同じにした判断が妥当か。言い回しの例の記号と数字が、記号16種と桁の仕様と矛盾しないか |
| 場の安全性 | 同室の参加者にとって、導入文が怖すぎないか |
| 既定の舞台 | ロビーで最初に選ばれる舞台が cabin になることに問題が無いか |

指摘と判断は次のとおりである。

| 箇所 | 指摘 | 判断 |
| --- | --- | --- |
| `titleEn` | `Snowed-In` は複合語の形容詞であり、レベル1〜2が見出しで読み取るのは難しい。作戦会議の画面は `titleEn` だけを見出しに出す（`Briefing.svelte`） | 直した。The Cabin in the Snow とした |
| `introEn` の1文目 | Snow is falling hard は誤りではないが、hard と組むなら It is snowing hard の方が口語として普通であり、語も平易である | 直した |
| `introJa` | 英語は the doors are locked であり「すべて」に当たる語が無い。lab.json は All the doors と言うため「すべて」と訳しているが、このパックの英語とは一致しない | 直した。「扉も閉まっている」とした |
| `introEn` の長さ | 2文目と3文目は lab.json より長いが、語は平易であり、作戦会議の画面に日本語も並ぶ | 変更しない |
| 錠の名前 | 3件とも自然であり、日本語の併記と一致する | 変更しない |
| 言い回しの例 | 赤い四角と青い星は記号16種に含まれる。確認の例 6, 1, 3, 9 は錠1と錠2の4桁と一致し、対応表の数字（0〜9、重複なし）とも矛盾しない | 変更しない |
| 規則の文 | 5規則はどれも舞台に依存しない作用であり、lab.md で直した範囲と対象の語を保つには同じ文を使うのが安全である | 作成者の判断を採る |
| 場の安全性 | 吹雪、消えかけた火、暗くなる前という時間制限だけであり、けがや死に触れていない。同室で遊ぶ場として怖すぎることはないと判断した | 変更しない |
| 既定の舞台 | ロビーで最初に選ばれる舞台が cabin になる（下の未解決の論点に記す） | コードを変えず、論点として残す |

`titleEn` を直した後も `titleJa` は「雪に閉ざされた山小屋」のまま残した。
閉ざされた状況は導入文の英語と日本語で伝わるため、題名の英語と日本語が完全に一致しなくても意味は保たれると判断した。

導入文以外の文言は次のとおりである。

## 未解決の論点

* lab.md の「未解決の論点」と「残した論点」は、規則の文が同じであるためこのパックにもそのまま当てはまる
* `storeroom` `radio room` がレベル1〜2に通じるかは確かめていない。錠の名前は日本語を併記するため、理解の妨げにはならないと見込むが、声に出して言えるかは別である
* 作戦会議の画面は `titleEn` だけを見出しに出し、`titleJa` を出さない（`Briefing.svelte`）。収録後レビューで `Snowed-In` を外して The Cabin in the Snow としたが、レベル1〜2に読めるかは学習者で確かめていない
* 導入文が英語3文で、lab.json（3文）と同じ文数だが1文が長い。作戦会議の90秒で読めるかは確かめていない
* 日本語の文言に新しい漢字（雪、暖炉、無線など）がある。収録時点ではフォントサブセットを作り直していなかったが、その後のコミット（a3baf58）で作り直した。サブセットに字が入ったことは、コミットの記述に依拠しており、収録後レビューでは確かめていない。収録後レビューの修正で新しく増えた日本語の字は無い
* ロビーは、ゲームを選んだ直後に舞台一覧の先頭を既定にする（`Lobby.svelte` の `contents[0]`）。舞台一覧はファイル名順に並ぶため（`generate:packs`）、既定は lab から cabin に変わった。ホストが舞台を選ばずに始めると、4観点のクロスレビューを経た lab ではなく、レビューの水準が低いこのパックで遊ぶことになる。E2Eは舞台を題名で選ぶため影響を受けない。既定を lab に戻すには、ファイル名の変更、生成器での並べ替え、ESCAPE CALLへの「おまかせ」の追加などの方法があり、どれを採るかはコードや命名の判断になるため、この記録では決めない

## レビューの限界

* 確認は作成時のAIの自己点検と、独立したAI1体の収録後レビューだけであり、lab.md の4観点クロスレビューより水準が低い
* 収録後レビューのAIは作成時のAIと同じモデルであり、同じ見落としを共有している可能性がある
* 規則の文の妥当性は lab.md の結論に依拠しており、このパックで改めて検討していない。lab.md の限界（同じモデルの4体で見落としを共有している可能性など）もそのまま引き継ぐ
* 導入文と錠の名前の英語が自然かは、AIの判断であり、英語話者の確認ではない
* 語彙の難度はAIの推定であり、学習者での確認ではない
* E2E（`pnpm e2e`）はこのパックでは実行していない。E2Eは「深夜の研究所」を題名で選んで通すため、このパックを通す経路は無い
