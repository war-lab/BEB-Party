# 遊び方ムービー

## 結論

収録10本の遊び方を1本ずつの縦動画（1080x1920 / 30fps / MP4）にする。

映像の素材は**実アプリを実際にプレイして撮ったスクリーンショット**であり、画面を描き起こさない。
撮影は Playwright、合成は Motion Canvas が担う。

MP4はリポジトリにコミットしない。ソース（撮影スクリプト・台本・シーン）だけを持ち、動画は都度生成する。

ソースは `movies/`、生成物は `movies/output/` に出る。

## なぜこの構成か

### 素材を実画面から撮る

遊び方を伝える対象は画面の操作である。
図解を描き起こすと、アプリを直したときに図だけが古くなり、しかも古くなったことに気づけない。

実画面を撮る方式では、撮り直せば最新の画面になる。
撮影は既存のE2Eの卓を立てる仕組み（`e2e/support/room.ts`）を再利用し、実際に各ゲームを進めて各ステージを撮る。
人数はゲームごとに、画面の違いが写る人数を選ぶ。

| ゲーム | 撮る人数 | 理由 |
| --- | --- | --- |
| DETECTIVES / DON'T SAY IT / ENGLISH RANKING / WHO WROTE THIS? / BLIND ROOM | 6人 | 撮影を作った時点の対応人数（5〜6人）の上限。対応人数を8人まで広げた（ADR-0033）後も、人数は見直していない |
| ESCAPE CALL | 3人 | 3種類の断片（錠の記号・数字の表・規則）が別々の端末に出る |
| SECRET RULE ENGLISH | 4人 | 3人以上で出る「試す英文を選ぶ」画面を写す |
| MIND MELD | 4人（2ペア） | 一致・近い語の申告と異議・前の2語・そろったペアの待ちが2ペアで全部出る。4人では1人の異議で申告が退けられないため、撮影の手順が分岐しない |
| TWO-HEADED SPEAKER | 6人（3ペア） | 対応人数の下限。「だれが当てた？」のシートに当てる側のペアが複数並ぶ |
| SECRET TEAMS | 6人（3対3） | 4人（2対2）では選べる味方が1人だけになり、味方を複数選ぶ回答の画面が写らない。奇数人数のように人数差の説明も要らない |

### Motion Canvasを使う（Remotionは使わない）

Remotionは**4人以上の組織で有料ライセンスが必須**である（$25/seat）。
不変条件1「有料サービスを導入しない」に抵触するため採らない。

Motion Canvas はMIT、ffmpegエクスポータもMITであり、費用が発生しない。

### 1ゲーム=1プロジェクト

レンダリングの単位はプロジェクトである。
1プロジェクトに全シーンを入れると、1本ずつ出すのに範囲の指定が必要になる。
範囲をUIから読む手段がない（`window.project` は露出していない。実測）ため、プロジェクトを分ける。

## 構成

```text
movies/
├── capture/                    # 撮影（Playwright）
│   ├── shots.spec.ts           #   10ゲームを実際にプレイして全ステージを撮る
│   └── support.ts              #   撮る側の関心（出力先・命名・待ちの安定化）
├── playwright.capture.config.ts
├── src/
│   ├── projects/<id>.ts        # 1ゲーム=1プロジェクト
│   ├── projects/<id>.meta      #   解像度・fps・エクスポータ
│   ├── scenes/<id>.tsx         #   薄い包み（vite-pluginが1ファイル=1シーンを要求する）
│   └── shared/
│       ├── script.ts           #   台本（10本分）
│       ├── howto.tsx           #   見せ方（間・切り替え・字幕）
│       ├── parts.tsx           #   共通部品
│       ├── theme.ts            #   配色・書体（tokens.cssの写し）
│       └── fonts.css           #   アプリと同じ書体を原本から読む
├── scripts/render.mjs          # レンダリング（エディタをPlaywrightで操作する）
├── assets/shots/               # 撮影した実画面（生成物・コミットしない）
└── output/                     # MP4（生成物・コミットしない）
```

## コマンド

| コマンド | 用途 |
| --- | --- |
| `pnpm --filter @beb/movies run capture` | 実アプリをプレイして素材を撮る。E2E用サーバは自動起動 |
| `pnpm --filter @beb/movies run dev` | Motion Canvasのエディタを開く（プレビューと手動レンダリング） |
| `pnpm --filter @beb/movies run render` | 10本をMP4へ書き出す。素材が先に必要 |
| `pnpm --filter @beb/movies run render -- detectives` | 1本だけ書き出す（見せ方を直したときの確認用） |
| `pnpm --filter @beb/movies run check` | 型検査 |

`render` は `capture` の成果物に依存する。素材がないと空の画面が写る。

## レンダリングの経路

Motion Canvas に文書化されたCLI・ヘッドレスのレンダリングは無く、エディタ（ブラウザ）が唯一の入口である。
フレームの生成はブラウザ側、MP4への書き出しはviteプラグインのサーバ側（`@motion-canvas/ffmpeg`）が担う。

そのため `scripts/render.mjs` は、viteのdevサーバを起動し、Playwrightでエディタを開いてRenderを押す。
この経路はエディタのUIに依存するため、Motion Canvasを上げたときに壊れうる。

## 見せ方の決めごと

**改行位置は台本が決める。** 字幕・箇条書き・タイトルはすべて行の配列で書き、自動折り返しを使わない。
折り返しに任せると助詞の途中で行が落ちる。
幅に収まらない行がある場合だけ、その節の文字を一律で縮める（`shared/parts.tsx` の `fitWithin`）。

**拡大（ズームイン）は入れない。** 実画面の文字が動くと読みにくく、静止画に寄る意味もない。

**部屋に入ってロビーで集まるまでの導線は各動画に入れない。** 全本で同じ内容であり、
遊び方の説明としては本題の前に置く必要がない。
素材（`common-home` / `common-lobby`）は撮り続けるが本編では使わない。

**字幕の帯の高さは行数から決める。** 行が増えても文字が帯からはみ出さない。

**締めの余韻は台本で指定できる。** 台本の `outro` で、最後の札（守ること）をいつもより長く残す秒数、その札が消える秒数、消えた後に何も出さない秒数を決める。
指定が無い台本は、他の札と同じ間（消える0.4秒、消えた後0.6秒）で終わる。
SECRET RULE ENGLISHは余韻を多めに取っている（長く残す1.6秒、消える1.1秒、消えた後1.8秒）。2026-10-14の依頼による。

## 台本の扱い

台本（`src/shared/script.ts`）は各ゲームの定数（締切秒数・得点・ラウンド数）の**写し**を持つ。

自動で参照しないのは、動画が「収録時点の仕様」を映すものだからである。
定数を変えたときに動画の字幕だけが自動で追従すると、古い動画と新しいアプリの食い違いに気づけない。

**ルールの数値を変えたら、同じPRで台本も直し、動画を撮り直す。**
数値の正本は各ゲームの `shared/games/<id>/src/game.ts` であり、台本はそこを出典とする。
対応人数だけは `server/games/<id>/src/module.ts` の `playerCount` が正本である。

2026-11-19のレビューで、SECRET RULE ENGLISHの台本が8人化（ADR-0033）の後も「2〜6人」のまま残っていたことが分かり、直して撮り直した。
人数の変更も、この規約の対象である。

### この規約は一度破られている

2026-09-08にDON'T SAY ITの `TABOO_COUNT` を 3/5/8/11/15 を経て 3/3/5/7/10 へ変えたとき、
台本は「3語→4語→5語＋条件」のまま残った。2026-09-09のレビューで指摘され、同時に
「人物を説明する」「人物名」という文言が物・場所のセット追加に追従していないことも見つかった。

**見落としやすい理由を書いておく。** `movies/` はデプロイ対象ではなく、
台本が古くても `pnpm check` も `pnpm test` も `pnpm validate:content` も通る。
機械では検出できないため、ゲームの定数や主題を変えるPRのチェック項目として扱う。

台本が写しを持つことの代償がこれである。写しをやめて定数を直接読む案は採らない
（上に書いた理由のとおり、古い動画と新しいアプリの食い違いに気づけなくなる）。

## 書体

アプリと同じ書体（Dela Gothic One / M PLUS Rounded 1c）を使う。
参照するのはリポジトリにある原本（`client/app/fonts-source/`）であり、複製しない。

配信用のサブセット（`client/public/fonts/`）は使わない。
字幕で使う文字が欠ける可能性がある。

ライセンスはOFLであり、表記は各 `fonts-source/*/OFL.txt` にある。

## ffmpegの扱い

MP4の書き出しには `@motion-canvas/ffmpeg` が引く ffmpeg / ffprobe のバイナリ（GPLv3）を使う。

これは手元で動画を作るための開発用ツールであり、アプリの配信物には含まれない。
出力したMP4はGPLの派生物にならない（バイナリを再配布せず、出力を成果物として扱うため）。

Linuxでは同梱バイナリへの `chmod u+x` が postinstall で走る。
pnpm 11は未承認のビルドをエラーにするため、`pnpm-workspace.yaml` の `allowBuilds` で宣言している。

## 素材の一覧

`capture/shots.spec.ts` が撮る画面。名前は `<ゲーム>-<ステージ>[-<役>]` とし、台本から引く。

| ゲーム | 撮る画面 |
| --- | --- |
| 共通 | ホーム、ロビー（ホスト・参加者）。撮るが本編では使わない |
| DETECTIVES | ブリーフィング、配役の伏せ面と役柄カード、捜査（レベル3・レベル1）、投票、開示 |
| DON'T SAY IT | ルール確認、交代（伏せ面とお題）、説明タイム（説明者・監視役・回答者）、正解の申告 |
| ENGLISH RANKING | 目標の伏せ面と目標カード、ブリーフィング、議論、順位の確定、承認、開示 |
| WHO WROTE THIS? | 質問の確認（レベル3・レベル1）、英作文（空・4語未満・提出可）、作者当て（指名側・作者側）、答え合わせ |
| BLIND ROOM | 部屋の確認、交代（伏せ面と見本）、配置（説明者・聞き手）、答え合わせ |
| ESCAPE CALL | 作戦会議、解錠（錠の記号・数字の表・規則）、入力と履歴（誤答1回・ヒント1回の後）、ふりかえり |
| SECRET RULE ENGLISH | 候補の確認（レベル1）、下書き、試す英文を選ぶ、報告と回答（作者・判定にかからなかった人）、規則を使って書く、結果 |
| MIND MELD | 遊び方の確認、語を出す（1回目・2回目の前の2語・そろったペアの待ち）、開示（申告する側・異議を出した判定者）、結果 |
| TWO-HEADED SPEAKER | 遊び方の確認、交代（伏せ面とお題・当てる側）、説明タイム（説明役・「だれが当てた？」のシート・当てる側）、結果 |
| SECRET TEAMS | 単語とテーマの伏せ面とカットイン、遊び方の確認、説明（手番の人・聞く人）、回答、結果 |

伏せ面のある画面は、**伏せ面を閉じた後に本体を撮る**。

SECRET RULE ENGLISHは、規則の絞り込みをE2Eと共用する（`e2e/support/secretrule.ts`）。
最後の英文は規則を満たし避ける候補を満たさない文を在庫から選び、結果の画面に正しく遊んだときのランクが写るようにする（任意の文で撮ってRANK Bが写った）。
報告と回答の画面は、上端に固定のタイマーバーがあるため、説明文までスクロールした後に少し戻してから撮る（説明文が隠れた）。

ESCAPE CALLは、錠が開いた直後に解錠の演出（UNLOCKED!）が画面に重なる。**演出が消えてから撮る**（実測で写り込んだ）。
答えは画面に出た断片から組み立てる。組み立て方はE2Eと共用する（`e2e/support/escapecall.ts`）。
閉じる前に撮ると全画面の伏せ面しか写らない（実測）。

MIND MELDは、出す語を撮影側の在庫（一般の名詞）から選ぶ。お題の英文の語と開示済みの語は送信ボタンが押せないため、押せる語を先頭から使う。
近い語の申告は `apple` / `apples` のような組で起こし、判定する側の1人が異議を出した後の画面を撮る。
開示の画面はカウントダウンが消えて全ペアの語が出てから撮る。

TWO-HEADED SPEAKERは、当てたペアを毎回「当てる側の先頭のペア」にして結果に順位の差を付ける。
E2Eと同じく順に散らすと全ペアが同点になり、結果に DRAW! が写った（実測）。
1枚ずつの申告は、当てる側の画面の「直前のお題」で受理を確かめてから次へ進める（E2Eと同じ確かめ方）。

SECRET TEAMSは、相手チームの1人だけが相手のテーマを外す回答にして、結果に勝敗が付くようにする。
説明の画面は、briefing の「読んだ」を押した位置のまま残るため、上端へ戻してから撮る（戻さないと手番の人が写らなかった。実測）。
自分の単語とテーマを画面から読む処理はE2Eと共用する（`e2e/support/secretteams.ts` の `readSeat`）。

字幕の帯の色（`GAME_ACCENT`）は、帯の上に濃い字を載せられる明るいトークンを10本で分ける。
明るいトークンは9色しかないため、SECRET TEAMSは黄をENGLISH RANKINGと共有する。動画は1本ずつ見るものであり、2本が並んで出る場面は無い。

## 未解決の論点

| 論点 | 内容 |
| --- | --- |
| 音声がない | ナレーションも効果音も入れていない。無音のまま字幕で読ませる前提であり、実際に見て足りるかは未確認 |
| 動画の置き場 | 生成物をリポジトリに置かない方針のため、配布は手元・Slack等に委ねる。アプリの「遊び方」から再生する形にはしていない |
| レンダリング経路の脆さ | エディタのUIを操作して出力する。Motion Canvasを上げるとセレクタが変わりうる |
| 撮影の再現性 | 事件・お題・配役はseedで決まるが、seedは共通コアが生成するため撮り直すと中身が変わる。字幕は中身に依存しない書き方にしている |
| 所要時間 | 実測は42.5〜52.7秒（収録時の7本）、MIND MELD 47.6秒・TWO-HEADED SPEAKER 49.9秒・SECRET TEAMS 46.7秒（2026-11-19）であり、いずれも狙いの40〜60秒に収まった（`movies/output/` の書き出しを `ffprobe` で計測）。読み切れる速さかは実際に見て判断する |
