# 遊び方ムービー

## 結論

収録4本の遊び方を1本ずつの縦動画（1080x1920 / 30fps / MP4）にする。

映像の素材は**実アプリを実際にプレイして撮ったスクリーンショット**であり、画面を描き起こさない。
撮影は Playwright、合成は Motion Canvas が担う。

MP4はリポジトリにコミットしない。ソース（撮影スクリプト・台本・シーン）だけを持ち、動画は都度生成する。

ソースは `movies/`、生成物は `movies/output/` に出る。

## なぜこの構成か

### 素材を実画面から撮る

遊び方を伝える対象は画面の操作である。
図解を描き起こすと、アプリを直したときに図だけが古くなり、しかも古くなったことに気づけない。

実画面を撮る方式では、撮り直せば最新の画面になる。
撮影は既存のE2Eの卓を立てる仕組み（`e2e/support/room.ts`）を再利用し、5〜6人で実際に各ゲームを進めて各ステージを撮る。

### Motion Canvasを使う（Remotionは使わない）

Remotionは**4人以上の組織で有料ライセンスが必須**である（$25/seat）。
不変条件1「有料サービスを導入しない」に抵触するため採らない。

Motion Canvas はMIT、ffmpegエクスポータもMITであり、費用が発生しない。

### 1ゲーム=1プロジェクト

レンダリングの単位はプロジェクトである。
1プロジェクトに4シーンを入れると、1本ずつ出すのに範囲の指定が必要になる。
範囲をUIから読む手段がない（`window.project` は露出していない。実測）ため、プロジェクトを分ける。

## 構成

```text
movies/
├── capture/                    # 撮影（Playwright）
│   ├── shots.spec.ts           #   4ゲームを実際にプレイして全ステージを撮る
│   └── support.ts              #   撮る側の関心（出力先・命名・待ちの安定化）
├── playwright.capture.config.ts
├── src/
│   ├── projects/<id>.ts        # 1ゲーム=1プロジェクト
│   ├── projects/<id>.meta      #   解像度・fps・エクスポータ
│   ├── scenes/<id>.tsx         #   薄い包み（vite-pluginが1ファイル=1シーンを要求する）
│   └── shared/
│       ├── script.ts           #   台本（4本分）
│       ├── howto.tsx           #   見せ方（間・切り替え・字幕）
│       ├── parts.tsx           #   共通部品
│       ├── theme.ts            #   配色・書体（tokens.cssの写し）
│       └── fonts.css           #   アプリと同じ書体を原本から読む
├── scripts/render.mjs          # レンダリング（エディタをPlaywrightで操作する）
├── assets/shots/               # 撮影した実画面（生成物・コミットしない）
└── output/                     # MP4（生成物・コミットしない）
```

## コマンド

| コマンド | 用途 |
| --- | --- |
| `pnpm --filter @beb/movies run capture` | 実アプリをプレイして素材を撮る。E2E用サーバは自動起動 |
| `pnpm --filter @beb/movies run dev` | Motion Canvasのエディタを開く（プレビューと手動レンダリング） |
| `pnpm --filter @beb/movies run render` | 4本をMP4へ書き出す。素材が先に必要 |
| `pnpm --filter @beb/movies run check` | 型検査 |

`render` は `capture` の成果物に依存する。素材がないと空の画面が写る。

## レンダリングの経路

Motion Canvas に文書化されたCLI・ヘッドレスのレンダリングは無く、エディタ（ブラウザ）が唯一の入口である。
フレームの生成はブラウザ側、MP4への書き出しはviteプラグインのサーバ側（`@motion-canvas/ffmpeg`）が担う。

そのため `scripts/render.mjs` は、viteのdevサーバを起動し、Playwrightでエディタを開いてRenderを押す。
この経路はエディタのUIに依存するため、Motion Canvasを上げたときに壊れうる。

## 台本の扱い

台本（`src/shared/script.ts`）は各ゲームの定数（締切秒数・得点・ラウンド数）の**写し**を持つ。

自動で参照しないのは、動画が「収録時点の仕様」を映すものだからである。
定数を変えたときに動画の字幕だけが自動で追従すると、古い動画と新しいアプリの食い違いに気づけない。

**ルールの数値を変えたら、同じPRで台本も直し、動画を撮り直す。**
数値の正本は各ゲームの `shared/games/<id>/src/game.ts` であり、台本はそこを出典とする。

## 書体

アプリと同じ書体（Dela Gothic One / M PLUS Rounded 1c）を使う。
参照するのはリポジトリにある原本（`client/app/fonts-source/`）であり、複製しない。

配信用のサブセット（`client/public/fonts/`）は使わない。
字幕で使う文字が欠ける可能性がある。

ライセンスはOFLであり、表記は各 `fonts-source/*/OFL.txt` にある。

## ffmpegの扱い

MP4の書き出しには `@motion-canvas/ffmpeg` が引く ffmpeg / ffprobe のバイナリ（GPLv3）を使う。

これは手元で動画を作るための開発用ツールであり、アプリの配信物には含まれない。
出力したMP4はGPLの派生物にならない（バイナリを再配布せず、出力を成果物として扱うため）。

Linuxでは同梱バイナリへの `chmod u+x` が postinstall で走る。
pnpm 11は未承認のビルドをエラーにするため、`pnpm-workspace.yaml` の `allowBuilds` で宣言している。

## 素材の一覧

`capture/shots.spec.ts` が撮る画面。名前は `<ゲーム>-<ステージ>[-<役>]` とし、台本から引く。

| ゲーム | 撮る画面 |
| --- | --- |
| 共通 | ホーム、ロビー（ホスト・参加者） |
| DETECTIVES | ブリーフィング、配役の伏せ面と役柄カード、捜査（レベル3・レベル1）、投票、開示 |
| DON'T SAY IT | ルール確認、交代（伏せ面とお題）、説明タイム（説明者・監視役・回答者）、正解の申告 |
| ENGLISH RANKING | 目標の伏せ面と目標カード、ブリーフィング、議論、順位の確定、承認、開示 |
| WHO WROTE THIS? | 質問の確認（レベル3・レベル1）、英作文（空・4語未満・提出可）、作者当て（指名側・作者側）、答え合わせ |

伏せ面のある画面は、**伏せ面を閉じた後に本体を撮る**。
閉じる前に撮ると全画面の伏せ面しか写らない（実測）。

## 未解決の論点

| 論点 | 内容 |
| --- | --- |
| 音声がない | ナレーションも効果音も入れていない。無音のまま字幕で読ませる前提であり、実際に見て足りるかは未確認 |
| 動画の置き場 | 生成物をリポジトリに置かない方針のため、配布は手元・Slack等に委ねる。アプリの「遊び方」から再生する形にはしていない |
| レンダリング経路の脆さ | エディタのUIを操作して出力する。Motion Canvasを上げるとセレクタが変わりうる |
| 撮影の再現性 | 事件・お題・配役はseedで決まるが、seedは共通コアが生成するため撮り直すと中身が変わる。字幕は中身に依存しない書き方にしている |
| 所要時間 | 1本あたり40〜60秒を狙って `hold` を置いたが、読み切れる速さかは実際に見て判断する |
