# 事件レビュー

## 結論

収録した事件ごとに、機械検証の結果・人手レビュー・机上プレイ・5人版の設計判断を1ファイルに記録する。

事件データそのものの正本は `content/detectives/*.json` であり、ここは「なぜその形にしたか」と「機械検証が担保しない部分をどう確認したか」の記録である。

新しい事件を追加したら、同じ節構成の記録をこのディレクトリに置く。

## 記録の書き方

各ファイルは次の節を持つ。書式は [cafe-theft.md](./cafe-theft.md) を見本とする。

* **結論**: 検証の通過状況、人手レビューの結果、未解決の論点
* **事件の骨格**: 盗難の時間帯と経路、各バリアントの嘘と「直接崩す証言」の対応表
* **機械検証の結果**: `pnpm validate:content` の出力
* **人手レビュー**: [基本設計/04](../基本設計/04_事件データと検証.md) のチェックリスト4項目
* **机上プレイ**: 全バリアントについて、矛盾に到達する会話の筋道を1つずつ
* **5人版の設計**: `merge5p` の統合先とその理由（[04](../基本設計/04_事件データと検証.md) の2基準）
* **検証が担保しないこと**: 機械検証では検出できない前提と、人が確認する項目
* **経緯**: 日付と出来事。レビューで何を直したか
* **付録A**: 事件データを意図的に壊し、想定した検証項目が落ちることを確かめた記録

## クロスレビューの経緯

| 巡 | 観点 | 主な結果 |
| --- | --- | --- |
| 1 | 構造と検証 | 対応表と5人版の統合先を検算し、記録の誤りを訂正した |
| 2 | 犯人の手札の自己整合 | 差し替えられない側のカードが自分の居場所を主張していると、犯人の手札だけで嘘が割れる。18キャラクター×7事件を洗い直し、状態カードへ書き換えた |
| 3 | 英語の質とゲーム体験 | 事件間で完全一致していた英文、レベル間で欠落していた情報、`hintJa` の体裁を直した |

2巡目で判明した設計基準は [04](../基本設計/04_事件データと検証.md) に反映済みである。
