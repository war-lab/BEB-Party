# プレイヤーアイコンの素材

アイコンの絵の正本は `player-icons-pixels.mjs` の48×48ドット絵（パレットと行データ）である。
IDと一覧の正本は `shared/core/src/player-icon.ts` の `PLAYER_ICONS`（[ADR-0022](../../../docs/adr/0022-プレイヤーアイコンはIDで持ち絵文字は表示層に置く.md)）。

## 内訳

| パス | 内容 |
| --- | --- |
| `player-icons-pixels.mjs` | 30件のパレット（最大20色）と48行48桁のドット。**ここが絵の正本** |
| `player-icons-sheet.png` | 29件分の元絵。生成AIで作ったラスタ画像（1535×1024、背景は緑） |
| `../scripts/generate-player-icons.mjs` | 書き出し |
| `../scripts/png.mjs` | PNGの符号化（RGBA8の最小実装） |
| `../../public/player-icons/<id>.png` | 生成物。96×96（48を2倍）。アプリが読むのはこちら |

## 作り直し方

```bash
pnpm --filter @beb/client-app run icons:generate
```

生成物はコミットし、CIで再生成との差分を検査する（基本設計/07）。
一覧から消したIDのファイルが残らないよう、生成時に出力先を作り直す。

倍率を渡すと大きく書き出せる（投影用など）。出力先は `icons-source/out-<辺>/` になり、コミットはしない。

```bash
node scripts/generate-player-icons.mjs 8   # 384x384
```

配布を96px（48の2倍）にしているのは、画面での表示が32〜64pxであり、常に縮小になるようにするためである。
ドット絵を拡大せずに済むため、縮小の平滑化だけで済む。

## 48×48のドット絵をどう作ったか

`player-icons-pixels.mjs` は `player-icons-sheet.png` から一度だけ機械的に変換したものである。
以降の修正はドット絵側（`player-icons-pixels.mjs`）を直接編集する。

変換の手順は次の通り。

1. 背景の緑を色相で判定して除く。判定は緑が他2チャンネルより60以上高い画素とし、`frog` と `alien` の緑を残す
2. 連結成分でアイコンを切り出す。番号のラベルは面積で区別して落とす（アイコンは13000画素以上、番号は350画素以下）
3. 正方形に中央寄せし、**不透明な画素だけを重み付きで平均**して48×48へ縮小する。背景の緑を混ぜないためである
4. 縁に残った緑かぶりを、近傍の非緑色で置き換える
5. 中間色を落とす（メディアンカットで最大20色、ディザなし）。アルファは被覆率0.42で2値化する

元絵はドットの格子を持たないため（色数約20万、エッジ間隔3〜15px）、機械的な縮小でしか格子に載せられない。
上記の手順は再現できるが、CIでは実行しない（元絵の解像度を変える必要が出たときだけ手作業でやり直す）。

次の3件は元絵を使わず、この形式で自作した。

| ID | 理由 |
| --- | --- |
| `blob` | 元絵が既存作品のキャラクターと同一の造形だった（権利の節） |
| `rabbit` | 元絵の耳が正方形に収まらず上で切れ、輪郭も破れた |
| `frog` | 縮小と量子化で輪郭と目が崩れ、全体が濁った |

機械的な変換が崩れるのは、元絵の細い線（うさぎの耳の輪郭、かえるの目の縁）が48×48では1マスを割るためである。
同じ症状が他のアイコンで出た場合も、該当分だけ打ち直す。

## 権利

27件は生成AIで作った `player-icons-sheet.png` を基にしている。
生成物に既存作品のキャラクターと同一の造形が1件（スライム）混入していたため、その1件は自作の `blob` に差し替えた。
`rabbit` と `frog` は見た目の都合で打ち直したものであり、権利の話ではない。

判断基準は `docs/ビジュアルデザイン.md` の権利面の注意とする。
**素材を追加・差し替えるときは、1件ずつ既存作品のキャラクターでないことを確認する。**
1件混入した実績があるため、確認は必須である。
